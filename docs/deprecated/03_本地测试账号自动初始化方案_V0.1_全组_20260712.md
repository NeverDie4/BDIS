# 生物医药数字信息系统本地测试账号自动初始化方案

> 版本：V0.1 方案稿  
> 日期：2026-07-12  
> 负责人：全组  
> 状态：待确认，尚未实现

## 1. 目标

为本地角色、路由、个人设置和权限联调提供可重复创建的测试账号，同时满足以下边界：

1. 不使用 Flyway 写入测试数据。
2. 不在代码或文档中保存明文密码、数据库密码或 Token。
3. 不在生产、共享测试或未明确启用的环境自动执行。
4. 重复运行结果一致，不产生重复用户、角色关系或脏数据。
5. 使用现有用户、角色和密码编码服务，不复制业务规则。

## 2. 推荐方案

在后端新增本地开发专用 `ApplicationRunner`：

```text
com.bdis.modules.auth.devseed
├── DevAccountSeedProperties
├── DevAccountSeedRunner
├── DevAccountSeedService
└── DevAccountDefinition
```

Runner 必须同时满足以下条件才执行：

```text
Spring Profile 包含 local
BDIS_DEV_ACCOUNT_SEED_ENABLED=true
BDIS_DEV_ACCOUNT_SEED_PASSWORD 已配置
数据库连接目标是 localhost 或 127.0.0.1
```

任一条件不满足时直接跳过，不能因为缺少测试账号阻止正常启动。

## 3. 账号清单

初始建议账号：

| 账号 | 角色 | 强制改密 | 用途 |
| --- | --- | --- | --- |
| `settings_admin` | `ADMIN` | 否 | 管理后台与公共设置 |
| `settings_teacher` | `TEACHER` | 否 | 教学角色可见性 |
| `settings_student` | `STUDENT` | 否 | 学习角色可见性 |
| `settings_collector` | `COLLECTOR` | 否 | 采集角色可见性 |
| `settings_reviewer` | `REVIEWER` | 否 | 审核角色可见性 |
| `settings_multi` | `TEACHER`、`REVIEWER` | 否 | 多角色并集 |
| `settings_force` | `STUDENT` | 是 | 强制改密流程 |

所有账号共用 `BDIS_DEV_ACCOUNT_SEED_PASSWORD` 指定的本地测试密码。Seeder 不输出该密码，只输出创建、跳过、修复的账号名称和角色编码。

## 4. 幂等规则

账号以 `username` 为稳定键：

1. 账号不存在：使用现有 `PasswordEncoder` 创建用户。
2. 账号已存在且由 Seeder 管理：校正启用状态、角色关系和强制改密标记。
3. 账号已存在但不是 Seeder 创建：记录警告并跳过，不覆盖成员账号。
4. 角色不存在或已停用：该账号创建失败并记录明确原因，不自动创建业务角色。
5. 角色关系采用差异更新，不删除清单之外的人工关系，除非启用严格重置模式。

建议使用 `remark=dev-account-seed` 标记 Seeder 管理的用户，不新增数据库字段。

## 5. 密码策略

1. 密码只从环境变量读取。
2. 使用项目现有 BCrypt `PasswordEncoder` 生成哈希。
3. 默认不在每次启动时重置已有账号密码，避免成员本地密码被意外覆盖。
4. 需要重置时额外启用 `BDIS_DEV_ACCOUNT_SEED_RESET_PASSWORD=true`。
5. `settings_force` 每次显式重置时同步设置 `must_change_password=1`。

## 6. 事务与失败处理

每个账号使用独立事务处理：

- 单个账号失败不回滚其他账号。
- 用户创建和角色绑定必须在同一事务内完成。
- 汇总输出 created、updated、skipped、failed 数量。
- 不记录密码、哈希、Token 和数据库连接凭据。

## 7. 启动方式

建议在根目录增加显式命令，而不是默认随所有后端启动执行：

```text
pnpm seed:accounts
```

该命令负责注入 `local` Profile 和 Seeder 开关。普通 `pnpm dev:api` 默认不插入账号；需要自动补齐账号的成员可在本地环境变量中主动启用。

## 8. 测试要求

实施时至少覆盖：

1. 未启用时不访问数据库。
2. 首次执行创建完整账号和角色关系。
3. 重复执行不产生重复数据。
4. 人工账号同名时不被覆盖。
5. 缺少角色时只影响对应账号。
6. 密码重置开关关闭时不更新密码哈希。
7. 非本地数据库目标拒绝执行。

## 9. 不采用的方案

- Flyway 初始化数据：测试账号会污染所有环境且难以安全携带密码。
- 固定 SQL 文件：无法复用 BCrypt、角色校验和用户创建规则。
- 默认启动自动插入：容易在共享环境产生非预期账号。
- 前端隐藏入口触发：账号初始化属于后端开发工具，不应暴露为产品功能。

## 10. 实施前确认

需要小组确认以下事项后再编码：

1. 是否接受固定测试用户名和统一环境变量密码。
2. Seeder 是否允许修复已有 Seeder 账号的角色关系。
3. 是否增加严格重置模式。
4. `settings_force` 修改密码后是否由下一次 Seeder 显式重置恢复测试状态。
