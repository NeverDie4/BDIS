# 生物医药数字信息系统需求分析

> 文档来源：根据 `biomed_function_breakdown.html`、`biomed_process_flow_user_container.html`、`biomed_use_case_overview.html` 三个项目文件整理。
>
> 文档定位：用于需求分析阶段，说明系统目标、业务边界、参与者、业务流程、功能需求、数据需求、权限安全需求、非功能需求与验收要点。

---

## 1. 项目概述

### 1.1 项目背景

生物医药相关教学、科研、培训、资源采集、评价申报和工作业绩认定过程中，会产生大量结构化数据、过程记录、图像文件、教学资料、研究材料、申报佐证材料和审核记录。若这些数据分散在个人电脑、移动端、线下表格或不同系统中，将导致资料难以共享、业务过程难以追踪、审核依据不统一、历史版本难以复核等问题。

因此，需要建设一个面向生物医药教学科研场景的数字信息系统，将中药材资源与生长数据、教学科研资源、教学培训记录、评价申报材料、工作业绩认定结果以及用户权限管理统一到同一平台中，实现数据集中管理、流程在线办理、资料规范归档和操作全过程审计。

### 1.2 建设目标

系统建设目标包括：

1. 建立统一的身份认证和权限管控体系，保证不同角色在授权范围内访问系统。
2. 建立中药材资源与生长数据管理体系，支持资源地图、生长数据采集、图谱比对、分析与溯源。
3. 建立教学科研资源库，支持实验课程、线上教学资源、课题研究资料和成果转化材料管理。
4. 建立教学培训过程管理能力，记录培训素材、培训安排、参与情况、结果评价和资料复用情况。
5. 建立评价体系与申报管理闭环，支持评价标准维护、过程跟踪、结果归档和申报材料沉淀。
6. 建立工作业绩认定管理流程，支持业绩填报、材料上传、审核认定、分类分级统计和标准维护。
7. 支持校内 SOAP 系统和手机 APP 端的数据交换，使外部系统、移动采集端与平台数据保持一致。
8. 提供查询、统计、下载、归档、备份和审计能力，保证数据可查、过程可追、结果可证。

## 2. 系统范围与边界

### 2.1 系统名称

生物医药数字信息系统。

### 2.2 系统边界

系统边界内包含六个功能域：

| 编号 | 功能域 | 业务定位 |
|---|---|---|
| FD-01 | 中药材资源与生长数据管理 | 建设中药材资源基础数据、生长数据、图像文件、地图查询、分析比对和溯源能力 |
| FD-02 | 教学科研资源管理 | 管理实验课程、线上教学资源、课题研究资料和成果转化材料 |
| FD-03 | 教学培训过程管理 | 管理培训素材、培训过程、培训结果、反馈评价和资料复用 |
| FD-04 | 评价体系与申报管理 | 管理评价指标、评价任务、评价结果、申报材料和佐证附件 |
| FD-05 | 工作业绩认定管理 | 管理业绩填报、审核认定、分类分级统计和认定标准 |
| FD-06 | 用户管理 | 管理账号、角色、权限、层级、数据范围和操作审计 |

### 2.3 系统外部对象

系统外部对象包括：

| 外部对象 | 与系统关系 |
|---|---|
| 手机 APP 端 | 用于现场采集中药材生长数据、图片、位置和记录，并与平台同步 |
| 校内 SOAP 系统 | 通过接口与平台进行数据交换 |
| 教师 / 学生 | 使用课程、资源、培训、查询、下载等服务 |
| 科研人员 / 科研机构 | 使用资源查询、课题研究、数据分析、成果转化和申报服务 |
| 培训人员 / 学员 | 参与培训过程记录、结果查询、反馈评价和资料复用 |
| 评价 / 申报人员 | 维护评价过程、管理申报材料、查询评价结果 |
| 业绩填报 / 审核人员 | 进行业绩填报、审核、退回、认定和统计 |
| 系统管理员 | 维护账号、角色、权限、层级、日志和系统基础配置 |

### 3.2 角色特征

1. 同一用户可能拥有多个角色，例如教师同时也是科研人员、业绩填报人员或评价申报人员。
2. 角色权限不仅控制菜单和功能，还需要控制数据范围、文件访问范围和业务办理范围。
3. 权限控制需要与组织、部门、团队、项目等层级关系结合。
4. 外部系统账号和手机 APP 端也需要纳入统一鉴权与审计体系。
5. 对审核、认定、下载、删除、导出等关键操作，应进行更严格的权限校验和日志记录。

## 4. 总体业务流程

### 4.1 权限管控总原则

用户管理不是单独孤立的业务模块，而是覆盖全部业务流程的统一管控体系。所有业务入口、数据采集、后台录入、文件上传、审核认定、查询下载和统计输出，都必须受到账号、角色、层级权限、数据范围和操作审计的约束。

### 4.2 总体流程

系统整体业务流程如下：

1. 用户或外部系统进入统一入口。
2. 系统进行身份识别、登录认证或接口鉴权。
3. 系统根据角色、层级和数据范围判断可访问的菜单、功能、文件和业务数据。
4. 用户进入对应业务模块，进行采集、录入、上传、查询、审核、认定或下载。
5. 数据进入统一数据与文件资源池，形成资源基础库、生长数据库、教学科研库和管理业务库。
6. 核心业务模块对数据进行管理、分析、跟踪、审核和归档。
7. 系统输出地图查询、教学科研服务、评价申报服务、业绩统计服务和操作日志查询服务。
8. 关键业务结果进入过程跟踪、历史归档、自动备份和审计记录。

### 4.3 数据采集与交换流程

| 步骤 | 业务动作 | 说明 |
|---|---|---|
| 1 | 移动端采集 | 手机 APP 采集中药材生长数据、图片、位置和现场记录 |
| 2 | 数据校验 | 对必填项、格式、图片、定位、采集时间等进行校验 |
| 3 | 数据同步 | 网络可用时上传平台；网络异常时可暂存并稍后同步 |
| 4 | 平台入库 | 平台保存采集记录、图片文件、采集人员、时间和来源 |
| 5 | 数据应用 | 数据用于地图查询、图谱比对、趋势统计、分析和溯源 |

### 4.4 后台资料管理流程

| 步骤 | 业务动作 | 说明 |
|---|---|---|
| 1 | 后台录入 | 管理人员录入品种、基地、课程、课题、培训、评价、业绩等资料 |
| 2 | 文件上传 | 上传图谱、图片、课件、视频、培训素材、申报附件、业绩佐证材料 |
| 3 | 分类归档 | 按资源类型、业务类型、所属项目、所属人员等维度分类 |
| 4 | 权限绑定 | 绑定可见范围、可下载范围、可审核范围 |
| 5 | 查询复用 | 授权用户可检索、查看、下载或复用相关资料 |

### 4.5 审核、追踪与归档流程

| 步骤 | 业务动作 | 说明 |
|---|---|---|
| 1 | 提交 | 用户提交评价结果、申报材料、业绩材料或其他需审核内容 |
| 2 | 审核 | 审核人员查看材料、填写意见、作出通过或退回决定 |
| 3 | 修改 | 被退回材料由提交人补充或修改后再次提交 |
| 4 | 确认 | 审核通过后形成正式业务结果 |
| 5 | 归档 | 系统保存结果、附件、审核意见、版本、操作人和时间 |
| 6 | 备份 | 关键数据和文件进入备份机制，支持历史追溯 |

## 5. 功能需求

## 5.1 FD-01 中药材资源与生长数据管理

### 5.1.1 业务目标

围绕重庆市中药材资源分布、生长过程数据和基础数据资产建设，形成可查询、可分析、可比对、可溯源的中药材资源管理能力。

### 5.1.2 主要参与者

教师、学生、科研人员、科研机构、采集人员、手机 APP、校内 SOAP 系统、系统管理员。

### 5.1.3 功能需求

| 功能项 | 需求描述 | 输出结果 |
|---|---|---|
| 重庆市中药材分布网络地图 | 支持按中药材品种、地点、基地、产地等条件查询资源分布 | 地图点位、资源列表、详情信息 |
| 品种与基地管理 | 维护中药材品种、基地、产地、地理位置、负责人、备注等基础数据 | 资源基础档案 |
| 生长数据采集 | 支持采集生长环境、形态指标、现场图片、采集时间、采集地点、采集人员等 | 生长数据记录 |
| 图片与文件归档 | 支持上传、下载、预览、分类、关联采集记录和业务对象 | 图片文件档案 |
| 手机 APP 数据同步 | 支持移动端采集后同步至平台，记录同步状态和异常信息 | 移动端采集记录 |
| SOAP 数据交换 | 支持与校内系统进行接口鉴权、请求、返回、入库和日志记录 | 接口交换记录 |
| 图谱比对 | 支持对中药材图谱或样本数据进行比对，输出比对结果 | 图谱比对结果 |
| 数据分析与趋势统计 | 支持按时间、品种、地点、基地等维度进行统计分析 | 分析报表 |
| 溯源查询 | 支持根据数据来源、采集人员、采集时间和业务流转记录追溯数据 | 溯源链路 |

### 5.1.4 典型用例

| 用例名称 | 前置条件 | 基本流程 | 异常处理 |
|---|---|---|---|
| 查看中药材分布地图 | 用户已登录并具备查询权限 | 选择品种或地点；系统展示地图点位；用户查看详情 | 无匹配数据时提示无结果 |
| 采集并上传生长数据 | 采集人员已通过 APP 鉴权 | 填写采集信息；拍照定位；提交上传；平台入库 | 网络异常时本地暂存，恢复后同步 |
| 调用 SOAP 数据接口 | 外部系统账号已授权 | 发起接口请求；系统鉴权；处理数据；记录日志 | 接口失败时记录错误并允许重试 |
| 进行图谱比对与溯源 | 用户具备分析权限 | 选择样本；执行比对；查看结果；查看来源链路 | 数据不足时提示补充样本或条件 |

## 5.2 FD-02 教学科研资源管理

### 5.2.1 业务目标

支撑实验教学、课题研究、线上学习和成果沉淀，形成统一的教学科研资源库。

### 5.2.2 主要参与者

教师、学生、科研人员、科研机构、系统管理员。

### 5.2.3 功能需求

| 功能项 | 需求描述 | 输出结果 |
|---|---|---|
| 实验课程存储 | 管理课程名称、课程简介、实验材料、实验步骤、教学资料和课程附件 | 实验课程档案 |
| 线上教学资源 | 维护视频教学、课件、文档、图片等资源，支持分类检索和权限访问 | 线上资源库 |
| 课题研究存储 | 管理课题内容、研究周期、参与人员、过程材料、阶段成果和附件 | 课题研究档案 |
| 成果转化支撑 | 关联研究数据、成果材料、转化记录、证明文件和后续应用情况 | 成果转化记录 |
| 资源查询与下载 | 授权用户可按课程、课题、资源类型、关键词等条件检索资源 | 查询结果和下载记录 |
| 版本与历史记录 | 资源变更时保留上传人、修改人、时间、版本说明和历史文件 | 资源版本记录 |

### 5.2.4 典型用例

| 用例名称 | 前置条件 | 基本流程 | 异常处理 |
|---|---|---|---|
| 管理实验课程资源 | 教师或管理员具备维护权限 | 新建课程；上传材料；保存并发布 | 上传失败时提示重试 |
| 查询线上教学资源 | 用户具备资源查看权限 | 输入关键词；筛选类别；查看或下载资源 | 无权限时隐藏下载按钮或提示无权限 |
| 管理课题研究资料 | 科研人员具备课题权限 | 新建课题；维护成员；上传过程材料；归档成果 | 成员变更时保留历史记录 |
| 维护成果转化材料 | 科研人员具备维护权限 | 关联课题与数据；上传成果材料；填写转化信息 | 材料不完整时提示补充 |

## 5.3 FD-03 教学培训过程管理

### 5.3.1 业务目标

面向教学培训活动，记录培训素材、培训安排、参与过程、学习结果、反馈评价和资料复用情况，形成完整培训档案。

### 5.3.2 主要参与者

教师、培训人员、学生、学员、系统管理员。

### 5.3.3 功能需求

| 功能项 | 需求描述 | 输出结果 |
|---|---|---|
| 培训素材制作与存储 | 管理培训课件、讲义、视频、案例、习题等素材 | 培训素材库 |
| 培训安排管理 | 维护培训主题、时间、地点、讲师、参与人员、培训对象 | 培训计划 |
| 教学培训过程记录 | 记录签到、学习过程、培训资料使用、课堂互动或过程附件 | 过程记录 |
| 教学培训结果记录 | 记录考核结果、反馈评价、学习成果、统计结果 | 培训结果档案 |
| 培训资料复用 | 支持教师、培训人员按权限检索和复用既有培训内容 | 复用记录 |
| 培训统计 | 按培训主题、人员、结果、反馈等维度生成统计数据 | 统计报表 |

### 5.3.4 典型用例

| 用例名称 | 前置条件 | 基本流程 | 异常处理 |
|---|---|---|---|
| 上传培训素材 | 用户具备培训素材维护权限 | 选择素材类型；上传文件；填写说明；保存归档 | 文件格式不符合时提示 |
| 记录培训过程 | 培训人员具备记录权限 | 选择培训活动；维护参与情况；上传过程资料 | 缺勤、未完成可作为异常状态记录 |
| 记录培训结果 | 培训人员具备结果维护权限 | 填写考核结果；录入反馈；生成统计 | 补考或补交反馈可追加记录 |
| 复用培训资料 | 用户具备查询权限 | 检索素材；查看详情；引用到新培训活动 | 无下载权限时仅允许在线查看 |

## 5.4 FD-04 评价体系与申报管理

围绕中药材评价过程、评价结果和申报材料形成闭环管理，支撑非遗申请等申报场景的数据沉淀与材料汇总。

### 5.4.2 主要参与者

评价管理人员、专家、教师、科研人员、申报人员、系统管理员。

### 5.4.3 功能需求

| 功能项 | 需求描述 | 输出结果 |

## 5.6 FD-06 用户管理

### 5.6.1 业务目标

作为系统入口和权限控制功能域，统一管理用户身份、角色权限、层级关系、数据访问范围和关键操作记录，支撑多类用户分层使用系统。

### 5.6.2 主要参与者

系统管理员、教师、学生、科研人员、培训人员、机构用户、外部系统账号、手机 APP 用户。

### 5.6.3 功能需求

| 功能项 | 需求描述 | 输出结果 |
|---|---|---|
| 用户账号管理 | 支持新增、编辑、停用、启用、查询用户账号 | 用户账号档案 |
| 用户类型管理 | 支持教师、学生、科研人员、培训人员、机构用户、外部系统账号等类型 | 用户分类 |
| 角色权限管理 | 支持按角色配置菜单、功能、文件、数据查询和业务办理权限 | 权限配置 |
| 层级管理 | 支持组织、部门、团队、项目等层级关系维护 | 层级关系 |
| 数据范围控制 | 按用户所属组织、团队、项目、角色控制可见和可操作数据 | 数据权限 |
| 登录认证 | 支持用户登录、身份识别、认证失败处理 | 登录状态 |
| 访问与操作记录 | 记录登录、查询、上传、审核、认定、下载等关键操作 | 审计日志 |
| 接口账号管理 | 对 SOAP 系统、手机 APP 端等接入方进行接口鉴权和访问记录 | 接口账号与日志 |

### 5.6.4 权限控制要求

1. 未登录用户不得访问需要认证的业务页面。
2. 用户登录后只能看到其角色允许访问的菜单和功能。
3. 用户只能查询、编辑、审核、下载其数据范围内的业务数据。
4. 审核、认定、标准维护、权限配置等高风险操作必须进行权限校验。
5. 所有关键操作都应写入审计日志。

## 8. 接口与外部集成需求

### 8.1 手机 APP 接入

手机 APP 端主要承担现场采集功能，需求包括：

1. 支持 APP 用户身份认证。
2. 支持采集中药材生长数据、图片、位置、备注等信息。
3. 支持数据本地暂存和网络恢复后同步。
4. 支持同步成功、同步失败、待同步等状态展示。
5. 支持平台记录 APP 采集来源和操作日志。

### 8.2 校内 SOAP 系统接入

校内 SOAP 系统主要承担外部数据交换功能，需求包括：

1. 接口调用前应完成接口账号鉴权。
2. 系统应支持请求、响应、数据入库和异常记录。
3. 接口失败时应记录失败原因，支持人工查看和必要的重试。
4. 交换数据应纳入统一数据资源中心。
5. 接口访问应写入审计日志。

### 8.3 文件上传与下载

系统需要支持图片、文档、课件、视频、申报附件、业绩佐证等文件管理：

1. 文件上传时应校验格式、大小和业务归属。
2. 文件下载应进行权限校验。
3. 文件应与业务对象关联，例如采集记录、课程、课题、评价任务、申报材料、业绩记录。
4. 关键文件应支持历史版本保留。
5. 删除文件或替换文件应写入操作日志。

## 9. 非功能性需求

### 9.1 易用性

1. 系统界面应按业务域清晰划分，便于教师、学生、科研人员、管理人员快速找到功能。
2. 表单应提供必填提示、格式校验和错误提示。
3. 查询页面应支持常用筛选条件和关键词检索。
4. 审核、提交、退回、下载等关键操作应给予明确反馈。

### 9.2 安全性

1. 系统必须提供统一身份认证。
2. 系统必须根据角色、层级和数据范围进行权限控制。
3. 权限不足时应阻止访问，不得仅依赖前端隐藏。
4. 关键操作必须记录审计日志。
5. 上传文件应进行基本安全校验，避免非法文件进入系统。
6. 接口调用应进行鉴权和访问记录。

### 9.3 可追溯性

1. 生长数据应可追溯到采集人员、采集时间、采集位置和数据来源。
2. 教学科研资源应可追溯上传人、版本和关联业务。
3. 评价与申报过程应可追溯标准版本、评价人员、评价意见和材料版本。
4. 业绩认定应可追溯填报、审核、退回、修改和最终认定过程。

### 9.4 可靠性

1. 移动端采集应支持网络异常情况下的暂存与后续同步。
2. SOAP 接口失败时应有日志和重试机制。
3. 文件上传失败时应提示用户重新上传。
4. 系统应支持关键数据备份和恢复。

### 9.5 性能

1. 普通查询、列表加载和详情查看应保持可接受响应速度。
2. 地图数据、图片资源和视频资源较多时，应采用分页、筛选或懒加载策略。
3. 大文件上传应有进度提示和失败提示。
4. 统计报表应支持按条件筛选，避免一次性加载过多数据。

### 9.6 可维护性

1. 业务模块应按六大功能域划分，降低模块耦合。
2. 评价标准、认定标准、角色权限等规则应支持配置化维护。
3. 日志、接口、文件、权限等公共能力应统一设计，供各业务模块复用。

### 9.7 兼容性

1. Web 端应兼容主流浏览器。
2. HTML 原型可通过 VSCode Live Server 本地预览。
3. 移动端采集功能应适配主流智能手机设备。

## 10. 异常与扩展需求

| 场景 | 处理要求 |
|---|---|
| 用户认证失败 | 拒绝访问并提示账号或认证异常 |
| 权限不足 | 隐藏无权限功能或提示无权限，不允许越权访问接口 |
| 移动端网络异常 | 数据本地暂存，网络恢复后同步 |
| SOAP 接口失败 | 记录日志、失败原因和请求内容，必要时支持重试 |
| 文件上传失败 | 提示失败原因，允许重新上传 |
| 查询无结果 | 提示无匹配数据，保留查询条件 |
| 审核材料不完整 | 退回并填写审核意见，提交人补充后再次提交 |
| 评价标准变更 | 保留历史版本，新任务使用新版本，旧结果保持原版本 |
| 认定标准变更 | 保留标准版本，历史认定结果可追溯 |
| 关键业务数据修改 | 记录修改人、修改时间、修改内容和原因 |

9. 系统能够按权限输出查询结果、统计结果、申报材料和下载文件。

### 12.2 数据验收

1. 核心业务数据字段完整，能满足查询、统计和追溯需求。
2. 文件能正确关联到业务对象。
3. 审核流程能保存审核意见、审核人、审核时间和审核结果。
4. 标准类数据支持版本记录。
5. 接口交换和移动端同步数据能够保留来源记录。

### 12.3 安全验收

1. 未登录用户不能访问受保护业务功能。
2. 权限不足用户不能进行越权查询、修改、下载或审核。
3. 关键接口具备鉴权控制。
4. 关键操作日志可查询、可追踪。
5. 用户、角色、层级、数据范围配置生效。

## 14. 结论

生物医药数字信息系统是一个以“数据资源 + 业务流程 + 权限管控 + 审计追溯”为核心的信息化平台。系统应以统一身份认证为入口，以六大功能域为业务主体，以统一数据与文件资源池为数据基础，以过程跟踪、审核归档和操作审计为管理保障，最终支撑教学、科研、培训、评价申报和工作业绩认定等业务的数字化协同运行。
