# 业绩认定默认角色授权说明

> 版本：V1.0
> 日期：2026-07-16
> 负责人：全组
> 状态：冻结期授权勘误

## 1. 适用范围

本文说明系统初始化后 `STUDENT`、`TEACHER`、`ADMIN`、`REVIEWER` 四类角色在业绩认定模块中的默认权限。实际访问仍同时受权限码、登录用户身份和后端数据范围校验约束；前端 tab 的可见性以 `performance:record:view` 为准。

## 2. 默认角色矩阵

| 角色 | 默认业绩权限 | 可见 tab 与可执行操作 | 数据范围 |
| --- | --- | --- | --- |
| `STUDENT`（学生） | `performance:standard:view`、`performance:record:view/create/update/submit` | 可进入业绩工作台；创建、编辑、维护材料与参与人、提交本人草稿或待修改业绩；可查看标准。 | 仅本人业绩。 |
| `TEACHER`（教师） | `performance:standard:view/manage`、`performance:record:view` | 可进入业绩工作台并查看本部门范围内业绩；可创建、编辑、发布、停用认定标准；不能创建、修改、提交或审核业绩。 | 业绩为本部门范围；标准操作由标准权限控制。 |
| `REVIEWER`（审核人员） | `performance:standard:view`、`performance:record:view/audit` | 可进入业绩工作台、查看数据范围内业绩并作出“通过认定”或“要求修改”决定；不能创建、修改、提交业绩或维护标准。 | 本部门范围；禁止审核本人业绩。 |
| `ADMIN`（系统管理员） | 全部 `performance:*` 权限 | 可执行业绩、审核、材料/参与人维护及标准全生命周期操作。 | 全量数据范围。 |

## 3. 教师入口修复

`/performance` 路由和门户顶部“业绩认定”tab 均要求 `performance:record:view`。此前教师仅拥有标准查看/维护权限，能够管理标准却无法进入该页面。

`V20260716_007__grant_teacher_performance_record_view.sql` 仅向 `TEACHER` 授予 `performance:record:view`，使其可见并使用标准工作区，同时维持既有职责边界：不新增业绩填报、修改、提交或审核权限。

## 4. 验证要点

1. 教师重新登录或刷新当前用户权限后，顶部栏应显示“业绩认定”，且 `/performance` 不再跳转至无权限页。
2. 教师可查看本部门范围内业绩和维护认定标准；“新增业绩”、业绩编辑/提交、审核操作不应出现且对应接口应返回无权限。
3. 学生仅能处理本人业绩；审核人员不能审核本人业绩；管理员保留全量访问能力。
