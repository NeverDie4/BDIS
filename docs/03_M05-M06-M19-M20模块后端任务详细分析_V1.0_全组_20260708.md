# M05、M06、M19、M20 模块后端任务详细分析

> 版本：V1.0  
> 日期：2026-07-08  
> 适用范围：模块分工、后端开发、接口联调、测试验收  
> 涉及模块：M05 文件资源模块、M06 操作审计模块、M19 SOAP 数据交换模块、M20 首页看板模块  
> 依据文档：后端业务逻辑任务分析、模块设计说明书、Java 类设计说明书、接口设计规范与接口清单、数据库详细设计说明书、业务任务总清单阅读版。

## 1. 四个模块的整体定位

本次分工涉及的 M05、M06、M19、M20 分别承担系统中的公共资源、审计追踪、外部交换和首页聚合能力。其中 M05、M06、M20 属于 P0 或 P0 支撑能力，M19 属于 P1 加分和集成展示能力。

| 模块 | 优先级 | 类型 | 一句话目标 |
| --- | --- | --- | --- |
| M05 文件资源模块 | P0 | 公共支撑 | 让图片、文档、视频、课件、图谱、申报附件、业绩材料可以统一上传、预览、下载并绑定业务对象。 |
| M06 操作审计模块 | P0 | 公共支撑 | 让关键操作可追踪，答辩时能说明“谁在什么时候对什么对象做了什么”。 |
| M19 SOAP 数据交换模块 | P1 | 集成能力 | 模拟或封装校内 SOAP 系统交换，完成请求、响应、解析、导入、失败重试和日志记录。 |
| M20 首页看板模块 | P0 | 展示聚合 | 登录后汇总药材、基地、采集、课程、待办和地图概览，让系统有整体运行视图。 |

四个模块之间的关系如下：

1. M05 被药材、采集、图谱、课程、课题、培训、申报、业绩等业务模块复用，是高扇入公共模块。
2. M06 被登录、文件、审核、归档、认定、SOAP 交换等关键流程复用，是审计底座。
3. M19 需要调用 M06 写同步日志和操作日志，并把外部数据转换为标准 DTO 后交给业务 Service。
4. M20 只读聚合业务数据，并按当前用户权限和数据范围输出统计、待办和地图概览。
5. M05 和 M06 应优先实现，否则后续业务模块会缺少文件和留痕能力。

## 2. 公共实现约束

### 2.1 接口路径约束

当前后端 `application.yml` 已配置：

```yaml
server:
  servlet:
    context-path: /api
```

因此 Controller 上的路径建议写为 `/files`、`/audit-logs`、`/soap-exchange-jobs`、`/dashboard` 等，不要在 Controller 再重复写 `/api/files`，避免最终路径变成 `/api/api/files`。

### 2.2 分层约束

四个模块均应遵循：

| 层级 | 要求 |
| --- | --- |
| Controller | 只做请求接收、参数校验、调用 Service、返回 VO，不直接操作数据库和文件系统。 |
| Service | 承担业务规则、权限校验、文件绑定、审计写入、事务控制、异常处理。 |
| Mapper | 只做数据库访问，复杂查询使用 XML。 |
| Entity | 与数据库表映射，使用 MyBatis-Plus 注解。 |
| DTO / Query / VO | 请求体、查询条件、返回视图分离。 |
| Converter | Entity、DTO、VO 转换，优先使用 MapStruct。 |

### 2.3 权限与审计约束

1. 登录接口外的接口均应校验 Bearer Token。
2. 文件下载、预览、日志查询、SOAP 交换详情、首页待办都需要结合角色和数据范围。
3. M05 文件访问必须写 `log_file_access`。
4. M19 SOAP 交换必须写 `soap_exchange_record` 和 `log_data_sync`。
5. M06 日志查询本身也需要权限控制，普通用户只能查本人或授权范围内日志，管理员可查全局。

## 3. M05 文件资源模块任务分析

### 3.1 模块目标

M05 文件资源模块统一处理图片、文档、视频、图谱、课件、培训素材、申报附件和业绩材料等文件资源。它不理解具体业务含义，不直接修改药材、课程、评价、申报、业绩等业务实体，只通过 `bizType + bizId + fileId` 建立业务关联。

最小完成标准：

1. 文件可以上传并生成文件元数据。
2. 文件可以按权限预览或下载。
3. 文件可以绑定到具体业务对象。
4. 文件访问行为可以写入日志。
5. 业务模块可以复用文件能力，不重复造文件表。

### 3.2 数据库任务

M05 直接涉及以下表：

| 表名 | 用途 | 优先级 |
| --- | --- | --- |
| `sys_file_resource` | 文件主数据，保存文件名称、类型、格式、大小、存储路径、上传人、上传时间等元数据。 | P0 |
| `sys_file_business` | 文件与业务对象关联，保存 `file_id`、`biz_type`、`biz_id`、`file_usage`。 | P0 |
| `log_file_access` | 文件预览、下载、播放等访问日志，属于 M05 与 M06 交叉表。 | P0 |

需要完成：

1. Flyway 建表脚本。
2. `FileResourceEntity`、`FileBusinessEntity`、`FileAccessLogEntity`。
3. `FileResourceMapper`、`FileBusinessMapper`、`FileAccessLogMapper`。
4. 常用索引：`file_type`、`uploader_id`、`uploaded_at`、`file_id`、`biz_type + biz_id`。
5. 文件逻辑删除字段与 MyBatis-Plus 全局逻辑删除配置保持一致。

### 3.3 后端类任务

| 类名 | 类型 | 需要完成的职责 |
| --- | --- | --- |
| `FileResourceController` | Controller | 上传、详情、列表、预览/下载、删除。 |
| `FileBusinessController` | Controller | 文件与业务对象绑定、解绑、按业务对象查询附件。 |
| `FileResourceService` | Service | 文件元数据维护、上传校验、删除校验、访问权限校验。 |
| `FileBusinessService` | Service | 维护 `bizType + bizId + fileId` 关系，避免重复绑定。 |
| `FileStorageService` | Service | 抽象存储能力，定义保存、读取、删除、获取路径。 |
| `LocalFileStorageServiceImpl` | ServiceImpl | 初版本地磁盘存储实现，使用 `bdis.file.storage-path`。 |
| `FileResourceConverter` | Converter | Entity 与 VO 转换。 |
| `BusinessReferenceValidator` | Component | 校验 `bizType` 合法、业务 ID 存在、当前用户有权限绑定或访问。 |

建议 DTO / Query / VO：

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| DTO | `FileUploadDTO` | 文件上传附加参数，如 `fileType`、`bizType`、`bizId`、`fileUsage`、`remark`。 |
| DTO | `FileBusinessBindDTO` | 绑定请求，包含 `fileId`、`bizType`、`bizId`、`fileUsage`。 |
| Query | `FileResourceQuery` | 按文件类型、上传人、业务对象、时间筛选。 |
| VO | `FileResourceVO` | 文件元数据返回。 |
| VO | `FilePreviewVO` | 预览信息，必要时包含可访问 URL 或内容类型。 |
| VO | `FileDownloadVO` | 下载信息，必要时包含文件名、大小、流信息。 |

### 3.4 REST 接口任务

| 功能 | 方法 | 建议 Controller 路径 | 说明 |
| --- | --- | --- | --- |
| 上传文件 | POST | `/files` | `multipart/form-data`，保存文件和元数据，可选立即绑定业务对象。 |
| 查询文件列表 | GET | `/files` | 支持 `businessType`、`businessId`、`fileType`、`uploaderId`、时间范围筛选。 |
| 查询文件详情 | GET | `/files/{fileId}` | 返回文件元数据，不直接返回真实物理路径。 |
| 获取文件内容 | GET | `/files/{fileId}/content` | `disposition=inline` 预览，`attachment` 下载。 |
| 删除文件 | DELETE | `/files/{fileId}` | 建议逻辑删除，删除前检查业务绑定和权限。 |
| 创建文件关联 | POST | `/file-relations` | 绑定 `fileId` 到 `bizType + bizId`。 |
| 删除文件关联 | DELETE | `/file-relations/{relationId}` | 解除绑定，不一定删除文件本体。 |

### 3.5 核心业务流程

文件上传绑定流程：

1. 用户携带 Token 请求上传。
2. 后端校验用户身份、文件大小、文件类型、扩展名、MIME。
3. `FileStorageService` 保存文件到本地目录。
4. `FileResourceService` 写入 `sys_file_resource`。
5. 如果请求中带 `bizType + bizId`，调用 `BusinessReferenceValidator` 校验业务对象。
6. `FileBusinessService` 写入 `sys_file_business`。
7. M06 或 `FileAccessLogService` 写上传日志。
8. 返回 `FileResourceVO`。

文件预览/下载流程：

1. 用户请求 `/files/{fileId}/content`。
2. 查询文件元数据，判断文件是否存在、是否删除、状态是否可用。
3. 根据文件绑定业务对象、上传人、角色权限判断是否可访问。
4. 读取文件流并设置 `Content-Type`、`Content-Disposition`。
5. 写 `log_file_access`。

### 3.6 权限与安全要求

1. 上传接口要求登录用户。
2. 下载和预览不能仅依赖静态 URL，必须经过后端权限校验。
3. 管理员可管理全部文件，普通用户只能管理自己上传或授权业务范围内文件。
4. 文件绑定时必须验证业务对象存在，避免绑定到不存在的 `bizId`。
5. 禁止上传危险后缀和超出限制的文件。
6. 本地存储路径必须使用服务端生成文件名，不能直接信任原始文件名。
7. 返回给前端的文件地址应是受控接口地址，不暴露服务器绝对路径。

### 3.7 异常处理任务

| 异常场景 | 后端处理 |
| --- | --- |
| 文件为空 | 返回 400，提示文件不能为空。 |
| 文件过大 | 返回 400，提示超过大小限制。 |
| 文件类型不允许 | 返回 400，提示文件格式不支持。 |
| 文件不存在 | 返回 404。 |
| 无下载权限 | 返回 403。 |
| 业务对象不存在 | 返回 400 或 404。 |
| 文件存储失败 | 抛出业务异常，事务回滚元数据。 |
| 重复绑定 | 返回幂等成功或提示已绑定，建议避免重复插入。 |

### 3.8 验收标准

1. 能上传图片、PDF、课件或视频类文件。
2. 能在文件列表看到文件元数据。
3. 能把文件绑定到采集记录、课程、申报或业绩等业务对象。
4. 能预览图片/PDF，能下载附件。
5. 删除文件后不能再下载，关联关系处理清晰。
6. 文件访问日志中能查到上传、预览、下载行为。
7. 非授权用户不能访问他人无权限文件。

## 4. M06 操作审计模块任务分析

### 4.1 模块目标

M06 操作审计模块负责记录登录、查询、上传、下载、审核、归档、认定、数据同步和外部交换等关键行为。它不控制业务流程，不决定业务状态，只负责日志写入、查询和追踪。

最小完成标准：

1. 登录成功和失败有记录。
2. 关键业务操作有记录。
3. 文件访问有记录。
4. SOAP 或同步操作有记录。
5. 管理员可以按条件查询日志，普通用户只能查看本人或授权范围内日志。

### 4.2 数据库任务

M06 涉及以下表：

| 表名 | 用途 | 优先级 |
| --- | --- | --- |
| `log_login` | 登录日志，记录登录结果、失败原因、IP、客户端。 | P0 |
| `log_operation` | 操作日志，记录后台管理、审核、上传、下载、删除等关键业务操作。 | P0 |
| `log_data_change` | 数据变更日志，记录重要业务表修改前后内容。 | P1 |
| `log_file_access` | 文件访问日志，记录预览、下载、播放等。 | P0 |
| `log_data_sync` | 数据同步日志，记录 APP 上传、批量导入、SOAP 同步等。 | P1 |

需要完成：

1. Flyway 建表脚本。
2. `LoginLogEntity`、`OperationLogEntity`、`DataChangeLogEntity`、`FileAccessLogEntity`、`DataSyncLogEntity`。
3. 对应 Mapper 与查询 XML。
4. 日志查询索引：操作人、模块、操作类型、时间、业务类型、业务 ID、同步类型、同步状态。

### 4.3 后端类任务

| 类名 | 类型 | 需要完成的职责 |
| --- | --- | --- |
| `AuditLogController` | Controller | 操作日志和数据变更日志查询。 |
| `LoginLogController` | Controller | 登录日志查询。 |
| `FileAccessLogController` | Controller | 文件访问日志查询。 |
| `DataSyncLogController` | Controller | 数据同步日志查询。 |
| `AuditLogService` | Service | 写入和查询操作审计。 |
| `LoginLogService` | Service | 写入和查询登录日志。 |
| `FileAccessLogService` | Service | 写入和查询文件访问日志。 |
| `DataSyncLogService` | Service | 写入和查询同步日志。 |
| `AuditAspect` | Component | 通过注解自动记录操作日志。 |
| `AuditLogAnnotation` | Annotation | 标记需要审计的方法，如模块名、操作类型、业务类型。 |

建议 DTO / Query / VO：

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| Query | `AuditLogQuery` | 按用户、模块、业务类型、业务 ID、操作类型、时间筛选。 |
| Query | `LoginLogQuery` | 按账号、用户、登录结果、时间筛选。 |
| Query | `FileAccessLogQuery` | 按文件、操作人、访问类型、时间筛选。 |
| Query | `DataSyncLogQuery` | 按同步类型、状态、来源、时间筛选。 |
| VO | `AuditLogVO` | 操作日志展示。 |
| VO | `LoginLogVO` | 登录日志展示。 |

### 4.4 REST 接口任务

| 功能 | 方法 | 建议 Controller 路径 | 说明 |
| --- | --- | --- | --- |
| 查询操作日志 | GET | `/audit-logs` | 支持用户、业务类型、业务 ID、操作类型、时间筛选。 |
| 查询操作日志详情 | GET | `/audit-logs/{logId}` | 查看单条日志。 |
| 查询登录日志 | GET | `/login-logs` | 管理员查询登录记录。 |
| 查询文件访问日志 | GET | `/file-access-logs` | 查询文件预览、下载记录。 |
| 查询数据同步日志 | GET | `/data-sync-logs` | 查询 APP、批量导入、SOAP 同步日志。 |

接口设计规范中只列出了 `/audit-logs`，实际开发可以根据页面需要扩展 `/login-logs`、`/file-access-logs`、`/data-sync-logs`，但要保持 RESTful 命名和统一响应。

### 4.5 审计写入点

M06 需要被以下流程调用：

| 来源模块 | 需要记录的操作 |
| --- | --- |
| M01 身份认证 | 登录成功、登录失败、退出登录。 |
| M05 文件资源 | 上传、预览、下载、删除、绑定、解绑。 |
| M09/M10 生长采集与审核 | 新增采集、提交审核、审核通过、审核退回、归档。 |
| M12 实验课程 | 新增课程、修改课程、发布课程、绑定资源。 |
| M16/M17 评价申报 | 新增评价任务、提交评分、确认结果、提交申报、审核申报、归档。 |
| M18 业绩认定 | 填报、提交、审核、退回、认定。 |
| M19 SOAP 数据交换 | 创建任务、执行交换、解析失败、导入成功、重试。 |

### 4.6 审计字段建议

操作日志至少应包含：

1. `operatorId`：操作人 ID。
2. `operatorName`：操作人名称或账号快照。
3. `operationModule`：模块编码，如 `M05_FILE`。
4. `operationType`：操作类型，如 `UPLOAD`、`DOWNLOAD`、`APPROVE`。
5. `bizType`：业务类型，如 `growth_record`。
6. `bizId`：业务 ID。
7. `operationResult`：成功或失败。
8. `errorMessage`：失败原因。
9. `ipAddress`、`userAgent`。
10. `operationTime`。

数据变更日志建议包含：

1. `tableName`。
2. `recordId`。
3. `beforeData`。
4. `afterData`。
5. `changeReason`。

### 4.7 权限要求

1. 管理员可查询全部日志。
2. 普通用户只能查询本人日志。
3. 审核人员可查询自己审核范围内的业务日志。
4. 日志详情中涉及敏感字段时应脱敏，例如密码、Token、文件绝对路径。
5. 日志只追加，不允许普通业务接口修改或删除。

### 4.8 验收标准

1. 错误密码登录后能看到失败日志。
2. 用户上传、下载文件后能看到文件访问日志。
3. 采集审核通过或退回后能看到操作日志。
4. SOAP 同步失败后能看到同步日志和失败原因。
5. 日志列表支持按时间、用户、模块、业务类型筛选。
6. 普通用户不能查看无权限日志。

## 5. M19 SOAP 数据交换模块任务分析

### 5.1 模块目标

M19 SOAP 数据交换模块用于模拟或封装校内 SOAP 系统的数据交换，包括请求构造、响应解析、数据转换、业务导入、交换日志记录和失败重试。

本模块是 P1 加分模块，答辩价值在于展示系统具备校内系统集成能力。初版可以做“模拟 SOAP 交换 + XML 解析 + 写交换记录 + 转入采集数据”的轻量闭环，不必接真实校内系统。

最小完成标准：

1. 能创建 SOAP 交换任务。
2. 能模拟执行一次 SOAP 请求或接收一段 XML。
3. 能保存请求 XML、响应 XML、状态和错误信息。
4. 能将 XML 转换为标准导入 DTO。
5. 成功时调用业务 Service 入库，失败时记录原因。
6. 失败任务可以手动重试。

### 5.2 数据库任务

M19 涉及以下表：

| 表名 | 用途 | 优先级 |
| --- | --- | --- |
| `soap_sync_task` | SOAP 同步任务配置，保存服务名、方法名、资源类型、方向、状态、最近同步时间。 | P1 |
| `soap_exchange_record` | SOAP 交换记录，保存请求 XML、响应 XML、交换状态、错误信息、调用人、调用时间。 | P1 |
| `log_data_sync` | 通用同步日志，保存同步类型、来源、结果和失败原因。 | P1 |

需要完成：

1. Flyway 建表脚本。
2. `SoapSyncTaskEntity`、`SoapExchangeRecordEntity`、`DataSyncLogEntity`。
3. `SoapSyncTaskMapper`、`SoapExchangeRecordMapper`、`DataSyncLogMapper`。
4. 状态枚举：`PENDING`、`PROCESSING`、`SUCCESS`、`FAILED`。
5. 方向枚举：`INBOUND`、`OUTBOUND`。
6. 来源枚举：`SOAP`、`IMPORT`、`MANUAL`。

### 5.3 后端类任务

| 类名 | 类型 | 需要完成的职责 |
| --- | --- | --- |
| `SoapSyncTaskController` | Controller | SOAP 同步任务创建、查询、详情、重试。 |
| `SoapExchangeController` | Controller | SOAP 交换记录查询、详情。 |
| `SoapSyncTaskService` | Service | 维护同步任务状态、触发执行、重试控制。 |
| `SoapExchangeService` | Service | 写请求响应记录、状态、错误信息。 |

### 5.5 核心业务流程

SOAP 入站导入流程：

1. 用户或系统创建 SOAP 交换任务。
2. 任务状态置为 `PENDING`。
3. 执行任务时状态置为 `PROCESSING`。
4. `SoapClient` 发起模拟请求或读取请求 XML。
5. `SoapExchangeService` 保存请求 XML 和响应 XML。
6. `SoapXmlParser` 解析 XML。
7. `SoapImportService` 转换为标准业务 DTO，如 `GrowthImportDTO`。
8. 调用对应业务 Service，例如 `GrowthRecordService.createFromSoap`。
9. 成功则任务状态置为 `SUCCESS`，写 `log_data_sync`。
10. 失败则任务状态置为 `FAILED`，保存错误信息，允许重试。

SOAP 重试流程：

1. 用户选择失败任务。
2. 后端校验任务状态必须为 `FAILED`。
3. 新增重试记录或更新任务重试次数。
4. 再次执行 XML 解析和导入。
5. 保留原失败记录，不覆盖历史交换记录。

### 5.6 与业务模块的边界

1. M19 不直接写 `herb_growth_record`、`herb_species` 等核心业务表。
2. M19 只负责解析、转换和记录交换过程。
3. 入库必须调用业务 Service，让业务模块自己校验药材、基地、采集时间、数据来源和权限。
4. 导入产生的业务记录需要标记 `sourceType = SOAP`。
5. 导入失败要能定位是 XML 格式错误、字段映射失败、业务校验失败还是数据库异常。

### 5.7 异常处理任务

| 异常场景 | 后端处理 |
| --- | --- |
| SOAP 请求失败 | 记录 `FAILED`、错误信息、请求参数。 |
| XML 格式错误 | 记录解析失败，不进入业务 Service。 |
| 字段缺失 | 返回导入失败，指出缺失字段。 |
| 业务对象不存在 | 调用业务 Service 后返回业务失败原因。 |
| 重复导入 | 需要基于外部编号或幂等键防重。 |
| 重试次数超限 | 拒绝重试或提示管理员处理。 |

### 5.8 验收标准

1. 能创建并查询 SOAP 交换任务。
2. 能执行一次模拟 SOAP 交换并生成交换记录。
3. 请求 XML、响应 XML、状态、错误信息可在详情中查看。
4. 模拟药材或采集数据可以转换为标准导入对象。
5. 成功导入后能在业务模块查到数据，来源为 SOAP。
6. 失败交换能查询失败原因并手动重试。
7. 同步过程写入 `log_data_sync`。

## 6. M20 首页看板模块任务分析

### 6.1 模块目标

M20 首页看板模块负责聚合系统统计数据，用于首页展示药材数量、基地数量、采集数量、课程数量、待审核事项、最近采集记录和地图概览。

本模块只做只读聚合，不控制任何业务状态，不修改业务数据。

最小完成标准：

1. 登录后首页能看到核心统计卡片。
2. 能看到最近采集记录。
3. 能看到当前用户权限范围内的待办事项。
4. 能看到地图概览统计。
5. 新增采集记录或审核状态变化后，看板数据能反映变化。

### 6.2 数据库任务

M20 可实时聚合业务表，也可使用快照表缓存。

| 表名 | 用途 | 优先级 |
| --- | --- | --- |
| `stat_dashboard_snapshot` | 保存首页看板统计快照，用于缓存药材数量、基地数量、采集数量、待办事项等统计数据。 | P0 可选 |

初版建议：

1. 优先实时聚合，减少快照同步复杂度。
2. 如果统计较慢，再按天写入 `stat_dashboard_snapshot`。
3. 快照字段 `dashboard_data` 可保存 JSON，适合存储汇总卡片、趋势、待办摘要。

### 6.3 后端类任务

| 类名 | 类型 | 需要完成的职责 |

3. 基地数量。

5. 当前用户可见范围内的数据。

### 6.6 权限与数据范围

M20 很容易被误写成“查全库统计”，但它仍必须受权限控制。

需要完成：

1. 管理员看全局统计。
2. 普通教师、学生、科研人员只看授权范围内数据。
3. 采集人员的待办主要是本人采集记录状态。
4. 审核人员的待办是其审核范围内待处理记录。
5. 统计 SQL 需要拼接数据范围条件，不能只对详情页做权限控制。

### 6.7 实时聚合与快照策略

初版推荐实时聚合：

1. 查询简单，开发快。
2. 数据新增后立即可见，适合演示。
3. 可以用 Redis 对热点统计做短时间缓存。

快照策略可作为扩展：

1. 每天或每小时生成 `stat_dashboard_snapshot`。
2. `snapshot_date` 保证唯一。
3. `dashboard_data` 保存 JSON 快照。
4. 首页优先读最新快照，必要时手动刷新。

### 6.8 验收标准

1. 登录后首页汇总接口能返回统计卡片数据。
2. 新增药材、基地、采集记录后，统计数量发生变化。
3. 最近采集接口能按时间倒序返回记录。
4. 审核人员能看到待审核采集，普通学生看不到不属于自己的审核待办。
5. 地图概览能返回区县和点位统计。
6. 看板接口不修改任何业务数据。

## 12. 结论

M05 和 M06 是本次分工中最基础的两个模块，应优先完成，因为文件和审计会被多个业务模块复用。M20 是 P0 演示入口，适合在药材、基地、采集和课程基础数据具备后快速接入。M19 是 P1 集成亮点，初版建议采用模拟 SOAP 交换完成“任务创建 -> XML 响应 -> 解析转换 -> 业务导入 -> 日志记录 -> 失败重试”的闭环。

推荐实现路径为：先完成 M06 的日志写入能力，再完成 M05 文件闭环，然后完成 M20 首页聚合，最后补齐 M19 SOAP 模拟交换与导入闭环。这样既能支撑 P0 主线，也能保留答辩时展示系统集成能力的亮点。
