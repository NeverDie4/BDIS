## 1. 说明

本文档用于说明 AI 小助手相关后端接口，供前端开发、后端联调和测试验收使用。

接口测试步骤、PowerShell 调用命令和联调排错记录请见测试说明文档；本文档只描述接口契约。

## 2. 通用约定

### 2.1 鉴权

除登录、初始化管理员等认证接口外，AI 小助手接口均需要 JWT 鉴权。

请求头：

```http
Authorization: Bearer <accessToken>
Content-Type: application/json; charset=utf-8
```

### 2.2 统一响应结构

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {},
  "timestamp": "2026-07-11T14:00:00+08:00"
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | String | 业务状态码 |
| message | String | 响应消息 |
| data | Object | 响应数据 |
| timestamp | String | 响应时间 |

常见状态码：

| code | 说明 |
| --- | --- |
| SUCCESS | 成功 |
| VALIDATION_ERROR | 参数校验失败或 AI 调用失败 |
| UNAUTHORIZED | 未登录或登录已失效 |
| FORBIDDEN | 无权限 |
| NOT_FOUND | 资源不存在 |
| CONFLICT | 资源冲突 |
| SYSTEM_ERROR | 系统异常 |

### 2.3 分页响应结构

```json
{
  "records": [],
  "page": 1,
  "size": 10,
  "total": 100
}
```

### 3.2 登录

`POST /api/auth/sessions`

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | String | 是 | 用户名 |
| password | String | 是 | 密码 |

| 字段 | 类型 | 说明 |

`GET /api/auth/me`

用于验证当前 Token 是否有效。

## 4. AI 小助手聊天接口

### 4.1 普通聊天 / RAG 聊天统一入口

`POST /api/herb/assistant/chat`

说明：

- `useRag=false` 或未传时，走普通聊天逻辑。
- `useRag=true` 且后端 RAG 已启用时，先检索知识库，再调用 AI 生成回答。
- RAG 回答会返回 `ragUsed=true` 和 `references`。

请求体：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| message | String | 是 | - | 用户问题，最长 1000 字 |
| sessionId | String | 否 | 后端生成或复用 | 会话 ID |
| userId | Long | 否 | 当前登录用户 | 用户 ID |
| source | String | 否 | - | 来源，如 `web`、`mobile`、`powershell` |
| useRag | Boolean | 否 | false | 是否启用 RAG |
| docType | String | 否 | - | 知识库文档类型，如 `rule` |
| topK | Integer | 否 | 配置值 | 检索返回数量 |

请求示例：

```json
{
  "message": "批次质量等级是怎么计算的？",
  "sessionId": "test-session-001",
  "source": "web",
  "useRag": true,
  "docType": "rule",
  "topK": 5
}
```

响应 `data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| sessionId | String | 会话 ID |
| answer | String | AI 回答 |
| ragUsed | Boolean | 是否使用 RAG |
| references | Array | RAG 引用来源；普通聊天为空数组 |

`references` 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| docId | Long | 文档 ID |
| docTitle | String | 文档标题 |
| chunkId | Long | 切片 ID |
| chunkIndex | Integer | 切片序号 |
| score | Double | 相似度分数 |
| contentPreview | String | 内容预览，不返回完整原文 |

响应示例：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "sessionId": "test-session-001",
    "answer": "根据知识库说明，批次质量等级主要结合平均置信度、识别数量和复核状态等因素计算。",
    "ragUsed": true,
    "references": [
      {
        "docId": 1,
        "docTitle": "批次评价规则",
        "chunkId": 12,
        "chunkIndex": 2,
        "score": 0.82,
        "contentPreview": "批次质量评价根据平均置信度、识别数量、复核状态..."
      }
    ]
  },
  "timestamp": "2026-07-11T14:00:00+08:00"
}
```

## 5. 独立 RAG 问答接口

### 5.1 RAG 知识库问答

`POST /api/herb/assistant/rag/chat`

说明：

- 该接口固定执行 RAG 问答。
- 后端优先使用向量库检索。
- 向量库不可用时，降级使用 MySQL `LIKE` 检索知识库切片内容。
- 只返回超过相似度阈值的引用。

请求体：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| message | String | 是 | - | 用户问题，最长 1000 字 |
| sessionId | String | 否 | 后端生成或复用 | 会话 ID |
| docType | String | 否 | - | 文档类型过滤 |
| topK | Integer | 否 | 配置值 | 检索数量 |
| source | String | 否 | - | 来源 |

响应 `data`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| sessionId | String | 会话 ID |
| answer | String | AI 回答 |
| references | Array | 知识库引用 |

## 9. RAG 检索规则

RAG 问答检索规则如下：

1. `topK` 未传时使用后端配置默认值。
2. `docType` 有值时，只检索对应类型文档。
3. 只检索启用状态的文档。
4. 只返回超过相似度阈值的切片。
5. 向量库不可用时，降级为 MySQL `LIKE` 检索切片内容。
6. 响应中不返回完整 embedding 和模型 raw result。

## 10. 调用示例

### 10.1 普通聊天

```powershell
$chatBody = @{
  message = "你好"
  sessionId = "test-session-001"
  source = "powershell"
} | ConvertTo-Json -Compress

Invoke-RestMethod `

  -Headers @{ Authorization = "Bearer $token" } `
  -ContentType "application/json; charset=utf-8" `
  -Body $chatBody
```

## 11. 前端对接建议

1. 普通聊天默认调用 `/api/herb/assistant/chat`，不传 `useRag`。
2. 知识库问答入口调用 `/api/herb/assistant/chat` 并传 `useRag=true`。
3. 调试 RAG 检索质量时，可直接调用 `/api/herb/assistant/rag/chat`。
4. 前端展示引用时建议只展示 `docTitle`、`chunkIndex`、`score` 和 `contentPreview`。
5. 当 `references` 为空时，前端仍正常展示回答，并提示“未命中知识库引用”。
