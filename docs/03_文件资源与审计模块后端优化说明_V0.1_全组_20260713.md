# 文件资源与审计模块后端优化说明 V0.1

## 1. 目标与边界

本轮优化解决文件模块跨业务硬编码、公开文件边界不清、数据库与物理文件删除时序不一致，以及日志随业务事务回滚、失败访问缺少记录等问题。

文件模块继续作为以下能力的唯一权威来源：

- 文件元数据、状态和受控内容地址；
- 私有或公开可见性切换；
- 文件访问日志；
- 物理文件保存和删除。

业务模块只通过 `FileBusinessAccessPolicy` 判断当前用户是否可以查看、绑定、解绑或发布业务对象的附件。Policy 不得读取或修改 `sys_file_resource`，不得返回物理存储路径。

## 2. 文件上传与发布流程

文件上传接口只接受私有文件：

```text
私有上传
  → 绑定业务对象
  → 业务模块审核或发布
  → 业务模块调用 FileResourceService.publishForBusiness
  → 文件模块校验绑定关系和 canPublish
  → 切换受控公开地址
```

不提供“上传时直接公开”的接口，也不提供允许用户任意切换文件可见性的通用 Controller。批量图谱导入同样先创建私有文件，再创建图谱业务对象、走正常 Policy 绑定，最后由图谱业务发布。运行期不再提供 `importPublic`、`registerPublic`、`bindSystem` 或自动扫描旧物理路径的旁路；历史物理路径数据只能通过显式、一次性的离线迁移任务处理。

业务内容撤回后，可以由业务模块调用 `makePrivateForBusiness` 撤销当前业务关系的公开要求。公开状态按 `sys_file_business.is_public` 逐关系维护；只有全部关系都撤销公开要求后，文件级 `access_level` 才回落为 `private`，避免共享文件被单个业务解绑时错误私有化。

## 3. FileBusinessAccessPolicy 接入契约

每个 `bizType` 必须注册一个 Spring Bean，实现：

```java
public interface FileBusinessAccessPolicy {
    String bizType();
    boolean exists(Long bizId);
    boolean canView(Long bizId);
    boolean canAttach(Long bizId);
    boolean canDetach(Long bizId);
    boolean canPublish(Long bizId);
}
```

注册表在启动时检查重复 `bizType`。未注册类型默认拒绝，禁止回退到 `file:resource:view` 等通用权限。

当前已注册：

| bizType | Policy 所属模块 | 发布判断 |
| --- | --- | --- |
| `herb_species` | 药材档案 | 药材编辑权限 |
| `herb_image` | 药材图片 | 图谱复核权限及数据范围 |
| `herb_atlas` | 标准图谱 | 图谱复核权限及数据范围 |
| `herb_growth_record` | 生长采集 | 采集审核权限及数据范围 |
| `herb_batch` | 采集批次 | 采集审核权限及数据范围 |
| `soap_sync_task` | SOAP 交换 | 禁止公开 |
| `map_point` | 地图点位 | 点位创建、更新或删除权限，由地图业务保存后绑定封面 |
| `eval_application` | 申报管理 | 申报审核权限及数据范围 |
| `perf_record` | 业绩管理 | 业绩审核权限及数据范围 |

科研和培训模块在完成业务状态与数据范围设计前不注册，文件访问默认拒绝。对应模块开发者必须在自己的模块包内提供 Policy，不得重新把业务表 SQL 写入公共文件模块。

## 4. 文件一致性策略

- 上传先保存物理文件；如果数据库事务未提交，事务完成回调清理物理文件。
- 删除先在数据库事务中删除关联和元数据；事务提交后才删除物理文件。
- 文件 `status != 1` 时，私有和公开内容接口均不可读取。
- 文件 `status != 1` 时也禁止建立新的业务关联。
- 删除已绑定文件前，对每一个业务关联执行 `canDetach`；对 `is_public = 1` 的已发布关系还必须执行 `canPublish`，防止上传者绕过业务权限直接删除已发布内容。
- 旧 `/api/files/uploads/**` 路径在 Security 中显式拒绝，服务层也拒绝解析此类字符串，不再承担历史兼容输入职责。
- `sys_file_business` 增加 `(file_id, biz_type, biz_id)` 唯一约束，避免并发重复绑定。
- `sys_file_business.is_public` 记录每条关系的发布状态；绑定、撤回和解绑后统一重算文件级 `access_level` 与受控内容地址。
- 业务附件使用关联查询和数据库分页，不再逐条查询文件或在内存中截取分页。

当前物理删除失败会记录 ERROR 日志但不回滚已经提交的数据库事务。生产环境仍建议增加持久化清理任务或对象存储生命周期策略。

## 5. 审计写入策略

操作、登录、文件访问和数据同步日志通过结构化事件快照写入：

```text
业务操作
  → 捕获用户、请求、Trace ID 和结果
  → 等待业务事务提交或完成
  → REQUIRES_NEW 独立事务写日志
```

- 成功日志在业务事务提交后写入，避免记录实际已回滚的成功操作。
- 失败登录在事务完成后写入，即使登录事务回滚也会保留。
- 文件预览、下载和拒绝访问均写 `log_file_access`，失败原因保存到 `failure_reason`。
- 日志写入失败不会阻断原业务请求，但会输出 ERROR 日志。
- 每个请求生成或透传 `X-Trace-Id`，操作日志和数据同步日志保存该标识。
- 请求参数只记录 Query/Form 参数，并对 password、token、secret 和 authorization 字段脱敏。

## 6. 查询与数据库变化

四类日志查询均支持 `startTime`、`endTime`；文件访问日志增加 `accessResult`。操作日志详情返回请求方法、请求地址、IP、User-Agent、Trace ID 和操作说明。

迁移脚本 `V20260713_004__harden_file_relations_and_audit_queries.sql` 包含：

- 文件关联去重和唯一约束；
- 文件访问失败原因；
- 登录结果、操作结果、访问结果及常用类型的时间组合索引；
- 文件访问级别和状态组合索引。

迁移脚本 `V20260714_001__track_file_business_visibility.sql` 增加关系级公开标记及组合索引，并将现有公开文件的业务关系回填为公开，以保持升级前后的可见性一致。

## 7. 后续事项

以下能力不属于本轮已完成范围：

- 病毒扫描、文件隔离区和内容签名识别；
- 审计事件持久化 Outbox、跨进程重试和死信队列；
- 日志归档、保留期限、分区和防篡改存储；
- 对象存储和 CDN 的签名 URL；
- 科研、培训等在研业务的 Policy。
- 历史物理路径数据如仍有残留，需要单独编写只运行一次、可审计、可回滚的离线迁移任务，不得恢复运行期兼容入口。

这些事项应在生产部署前按数据安全等级继续完善。
