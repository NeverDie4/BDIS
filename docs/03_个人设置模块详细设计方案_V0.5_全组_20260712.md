# 生物医药数字信息系统个人设置模块详细设计方案

> 版本：V0.5 评审稿  
> 日期：2026-07-12  
> 负责人：全组  
> 状态：评审通过，V0.5 基线已于 2026-07-12 实施

> 维护说明：本文档保留已确认的设计边界和扩展约定，不作为运行状态清单。接口行为、数据库迁移和前端注册表以后续代码与自动化测试为事实来源；角色业务设置字段仍需由对应模块负责人确认后扩展。

## 1. 文档目的

本文档在现有用户、角色、JWT、个人主页和门户导航实现基础上，设计统一的个人设置模块，包括：

1. 个人资料维护。
2. 密码修改与认证会话管理。
3. 通用界面和通知偏好。
4. 教师、学生、采集人员、审核人员等角色专属设置分区。
5. 前端设置 Tab 的组件化注册和角色可见性控制。
6. 对应 REST API、数据库表、字段、索引和安全边界。

本稿已经完成评审并作为首期实现基线。实施仍遵守原边界：不修改其他成员负责的课程、移动端和业务页面，角色专属设置只提供注册与访问控制扩展点。

## 2. 现状审计

### 2.1 已有能力

| 范围     | 当前实现                            | 可复用能力                                      |
| -------- | ----------------------------------- | ----------------------------------------------- |
| 当前用户 | `GET /api/auth/me`                  | 返回用户 ID、账号、姓名、组织、部门、角色和权限 |
| 个人主页 | `/profile`                          | 展示身份、角色、权限和有权查看的审计日志        |
| 用户资料 | `sys_user`                          | 已有姓名、手机号、邮箱、组织、部门、头像地址    |
| 登录     | `POST /api/auth/sessions`           | 签发包含 `jti`、`iat`、`exp` 的 JWT             |
| 当前退出 | `DELETE /api/auth/sessions/current` | 使用 Redis 黑名单使当前 JWT 失效                |
| 权限控制 | RBAC、`PermissionGate`、路由守卫    | 可控制页面、按钮和设置分区可见性                |
| 前端数据 | Axios、Zustand、TanStack Query      | 可用于设置查询、缓存和更新                      |

### 2.2 缺失能力

| 缺口                     | 影响                                              |
| ------------------------ | ------------------------------------------------- |
| 没有 `/settings` 页面    | 门户设置按钮目前只能跳转个人主页                  |
| 没有个人偏好表           | 设置无法跨设备持久化                              |
| 没有个人资料自助更新接口 | 只能通过管理员用户接口修改资料                    |
| 没有修改密码接口         | 用户不能自行更新密码                              |
| 没有认证会话表           | JWT 只有 Redis 黑名单，无法列出设备或撤销指定会话 |
| 没有角色设置分区注册机制 | 容易在页面内散落角色判断                          |
| 通知内容为前端静态数据   | 当前没有通知订阅或偏好持久化能力                  |

### 2.3 现有表的适配结论

`sys_user` 适合保存稳定的身份字段，不适合继续增加主题、列表密度、提醒时间、采集偏好等大量可扩展字段。个人设置应使用独立偏好表。

JWT 已包含唯一 `jti`，可以在不保存原始 Token 的前提下建立认证会话记录。Redis 继续负责高频黑名单检查，MySQL 负责会话列表、设备信息和审计查询。

## 3. 总体设计决策

### 3.1 页面边界

| 路由                  | 定位                           | 本模块是否实现                         |
| --------------------- | ------------------------------ | -------------------------------------- |
| `/profile`            | 个人身份、角色、权限和审计概览 | 保留，后续补充“编辑资料”“进入设置”入口 |
| `/settings`           | 当前用户个人设置               | 本模块目标页面                         |
| `/dashboard/settings` | 全局系统参数、平台配置         | 不属于个人设置，后续单独设计           |

### 3.2 不为每个角色复制设置页面

所有用户使用同一个 `/settings` 页面。页面由公共设置分区和角色设置分区组合而成：

- 公共分区：账号资料、安全、界面、通知。
- 角色分区：教学、学习、采集、审核。
- 多角色用户：显示各角色分区的并集。
- 管理员：默认只显示公共个人设置；全局系统配置不混入个人设置。

前端角色判断只负责用户体验。后端必须按用户身份、角色和命名空间策略再次校验，不能依赖前端隐藏 Tab 保证安全。

### 3.3 偏好数据采用命名空间存储

偏好按命名空间保存为 JSON：

```text
common
appearance
notification
teaching
learning
collection
review
```

选择该方案的原因：

1. 避免在 `sys_user` 上持续增加低频偏好字段。
2. 新业务模块可以注册新命名空间，不需要为每个角色创建一张表。
3. 每个命名空间可以独立读取、保存、重置和做乐观锁控制。
4. 课程和移动端模块可以只实现自己的验证器，不修改设置核心模块。

风险是 JSON 缺少数据库列级类型约束，因此后端必须使用命名空间处理器进行白名单字段校验，禁止直接保存任意 JSON。

## 4. 数据库设计

### 4.1 `sys_user` 新增字段

| 字段名                 | 类型     | 必填 | 默认值 | 说明                                                |
| ---------------------- | -------- | ---- | ------ | --------------------------------------------------- |
| `password_changed_at`  | DATETIME | 否   | NULL   | 最近一次密码变更时间，用于安全展示和 Token 失效判断 |
| `must_change_password` | TINYINT  | 是   | 0      | 是否要求下次登录后修改密码：0 否，1 是              |

不新增主题、语言、通知、角色偏好等字段。

建议索引：无需为上述字段单独建索引。

### 4.2 `sys_user_preference`：用户偏好表

表用途：保存用户在不同设置命名空间下的个性化覆盖值。

| 字段名                 | 类型        | 必填 | 默认值            | 键/索引 | 说明                            |
| ---------------------- | ----------- | ---- | ----------------- | ------- | ------------------------------- |
| `id`                   | BIGINT      | 是   | AUTO_INCREMENT    | PK      | 主键                            |
| `user_id`              | BIGINT      | 是   | 无                | UK/IDX  | 用户 ID，逻辑关联 `sys_user.id` |
| `preference_namespace` | VARCHAR(50) | 是   | 无                | UK/IDX  | 设置命名空间                    |
| `preference_data`      | JSON        | 是   | 无                |         | 用户覆盖值，不保存默认值        |
| `schema_version`       | INT         | 是   | 1                 |         | 命名空间数据结构版本            |
| `created_at`           | DATETIME    | 是   | CURRENT_TIMESTAMP |         | 创建时间                        |
| `updated_at`           | DATETIME    | 是   | CURRENT_TIMESTAMP |         | 更新时间                        |
| `version`              | INT         | 是   | 0                 |         | 乐观锁版本号                    |

约束和索引：

```text
PRIMARY KEY (id)
UNIQUE KEY uk_sys_user_preference_user_namespace (user_id, preference_namespace)
KEY idx_sys_user_preference_namespace (preference_namespace)
```

设计说明：

- 不使用逻辑删除。重置命名空间时可以删除该行，恢复系统默认值。
- 不保存密码、Token、密钥、文件内容等敏感信息。
- 单个 `preference_data` 序列化后建议限制为 16 KB。
- `schema_version` 用于后端升级旧偏好数据，不等同于乐观锁 `version`。
- 命名空间枚举由后端注册器维护，不在数据库增加固定 CHECK，避免每新增业务模块都修改约束。

示例：

```json
{
  "defaultLandingPath": "/",
  "timezone": "Asia/Shanghai",
  "locale": "zh-CN"
}
```

### 4.3 `auth_user_session`：用户认证会话表

表用途：保存可查询、可撤销的登录会话元数据，不保存原始 JWT。

| 字段名           | 类型         | 必填 | 默认值            | 键/索引 | 说明                                            |
| ---------------- | ------------ | ---- | ----------------- | ------- | ----------------------------------------------- |
| `id`             | BIGINT       | 是   | AUTO_INCREMENT    | PK      | 主键                                            |
| `session_id`     | VARCHAR(64)  | 是   | 无                | UK      | 对前端公开的会话标识                            |
| `user_id`        | BIGINT       | 是   | 无                | IDX     | 用户 ID                                         |
| `token_jti`      | VARCHAR(64)  | 是   | 无                | UK      | JWT 的 `jti`，不是 Token 内容                   |
| `client_type`    | VARCHAR(30)  | 是   | `web`             | IDX     | `web`、`mobile`、`unknown`                      |
| `device_name`    | VARCHAR(100) | 否   | NULL              |         | 解析后的设备名称                                |
| `ip_address`     | VARCHAR(64)  | 否   | NULL              |         | 最近 IP                                         |
| `user_agent`     | VARCHAR(500) | 否   | NULL              |         | 客户端 User-Agent                               |
| `issued_at`      | DATETIME     | 是   | 无                |         | Token 签发时间                                  |
| `last_active_at` | DATETIME     | 是   | 无                | IDX     | 最近活动时间                                    |
| `expires_at`     | DATETIME     | 是   | 无                | IDX     | Token 到期时间                                  |
| `revoked_at`     | DATETIME     | 否   | NULL              |         | 撤销时间                                        |
| `revoke_reason`  | VARCHAR(100) | 否   | NULL              |         | `logout`、`password_changed`、`user_revoked` 等 |
| `session_status` | VARCHAR(20)  | 是   | `active`          | IDX     | `active`、`revoked`、`expired`                  |
| `created_at`     | DATETIME     | 是   | CURRENT_TIMESTAMP |         | 创建时间                                        |
| `updated_at`     | DATETIME     | 是   | CURRENT_TIMESTAMP |         | 更新时间                                        |

约束和索引：

```text
PRIMARY KEY (id)
UNIQUE KEY uk_auth_user_session_session_id (session_id)
UNIQUE KEY uk_auth_user_session_token_jti (token_jti)
KEY idx_auth_user_session_user_status (user_id, session_status, expires_at)
KEY idx_auth_user_session_last_active_at (last_active_at)
```

安全规则：

1. 禁止保存 JWT 原文和签名。
2. 撤销会话时同时更新 MySQL 状态并写入 Redis 黑名单。
3. 会话列表只返回当前用户自己的记录。
4. `last_active_at` 不应每次请求都写库，建议每 5 至 10 分钟节流更新。
5. 定时任务可以将过期活动会话标记为 `expired`，历史记录按保留策略清理。

#### 与现有 JWT 过滤器的集成

`auth_user_session` 不能只用于页面展示，必须参与 Token 有效性判断：

1. `JwtUtils.generate` 建议改为返回 Token 和对应 Claims 的签发结果对象，避免生成后再次解析 Token 才能取得 `jti`。
2. 登录成功时先创建活动会话记录，再向客户端返回 Token。
3. `JwtAuthenticationFilter` 解析 JWT 后，根据 `jti` 检查会话是否存在、是否活动、是否过期。
4. MySQL 会话状态是撤销事实来源，Redis 黑名单是高频加速层，不能出现“数据库已撤销但过滤器完全不检查”的情况。
5. Redis 不可用时，应根据明确的安全策略回退到 MySQL 会话状态检查，而不是静默放行。
6. 当前会话识别需要把 `jti` 放入认证详情或请求级 `SessionContext`，用于会话列表标记 `current=true`。
7. 上线前签发且没有数据库会话记录的旧 JWT，需要选择“部署后统一重新登录”或“在一个 Token TTL 内兼容旧 Token”，不能无规则混用。
8. 当 `password_changed_at` 晚于 JWT `iat` 时，过滤器应拒绝该 Token。

### 4.4 暂不新增通知消息表

本阶段只设计通知偏好，不实现完整通知中心。通知消息、已读状态、站内信投递等属于独立通知模块，不能为了设置页顺带创建不完整的通知业务表。

`notification` 命名空间只保存用户是否接收某类通知和渠道偏好。

### 4.5 Flyway 迁移建议

评审通过后新增一份 migration，内容包括：

1. 为 `sys_user` 增加两个密码安全字段。
2. 创建 `sys_user_preference`。
3. 创建 `auth_user_session`。

当前最新 migration 为 `V20260712_001__add_atlas_import_permission.sql`。若实施时没有其他成员占用版本，可使用：

```text
V20260712_002__add_user_settings_and_sessions.sql
```

正式创建前必须再次检查最新版本号，不能提前修改或占用其他成员 migration。

## 5. 设置命名空间字段设计

### 5.1 `common`

| 字段                 | 类型   | 默认值          | 说明                           |
| -------------------- | ------ | --------------- | ------------------------------ |
| `defaultLandingPath` | String | 按权限计算      | 登录后默认页面                 |
| `timezone`           | String | `Asia/Shanghai` | 展示时区                       |
| `locale`             | String | `zh-CN`         | 界面语言，第一期只允许 `zh-CN` |

`defaultLandingPath` 必须是站内已登记路由。角色变化后如果路径失去权限，登录流程应回退到权限允许的默认页面。

### 5.2 `appearance`

| 字段             | 类型    | 默认值        | 可选值                          |
| ---------------- | ------- | ------------- | ------------------------------- |
| `contentDensity` | String  | `comfortable` | `comfortable`、`compact`        |
| `sidebarMode`    | String  | `auto`        | `auto`、`expanded`、`collapsed` |
| `reduceMotion`   | Boolean | false         | true、false                     |

第一期不设计深色主题，避免在门户和后台样式尚未完全统一时引入第二套主题。

### 5.3 `notification`

| 字段                    | 类型    | 默认值  | 说明               |
| ----------------------- | ------- | ------- | ------------------ |
| `siteEnabled`           | Boolean | true    | 是否接收站内提醒   |
| `emailEnabled`          | Boolean | false   | 是否接收邮件提醒   |
| `taskReminderEnabled`   | Boolean | true    | 是否接收任务提醒   |
| `reviewReminderEnabled` | Boolean | true    | 是否接收审核提醒   |
| `quietHoursEnabled`     | Boolean | false   | 是否启用免打扰时段 |
| `quietHoursStart`       | String  | `22:00` | 免打扰开始时间     |
| `quietHoursEnd`         | String  | `08:00` | 免打扰结束时间     |

当用户没有邮箱时，`emailEnabled` 必须被后端归一化为 false。

### 5.4 `teaching`

初始角色：`TEACHER`。

建议预留字段：

| 字段                         | 类型    | 默认值 | 说明                   |
| ---------------------------- | ------- | ------ | ---------------------- |
| `defaultCourseView`          | String  | `list` | 课程默认视图           |
| `taskReminderAdvanceMinutes` | Integer | 60     | 教学任务提前提醒分钟数 |
| `showStudentStatistics`      | Boolean | true   | 是否默认显示学生统计   |

课程模块由其他成员实现，本专项只保留命名空间、Tab 注册接口和验证扩展点，不修改课程业务页面或接口。

### 5.5 `learning`

初始角色：`STUDENT`。

建议预留字段：课程提醒、资源展示模式、学习记录可见性。具体字段等待课程模块接口稳定后确认。

### 5.6 `collection`

初始角色：`COLLECTOR`。

建议预留字段：默认地图图层、自动保存间隔、图片质量和定位精度。移动端由其他成员负责，本专项不修改移动端页面，只保证 Web 设置接口可以扩展。

### 5.7 `review`

初始角色：`REVIEWER`。

建议预留字段：默认审核队列、完成后自动打开下一条、截止时间提醒。具体字段由审核业务流程确认后落地。

## 6. REST API 设计

所有路径均以 `/api` 为统一前缀，以下表格省略此前缀。所有接口只操作当前登录用户，不允许通过 Query 或 Body 传入其他用户 ID。

### 6.1 个人资料

#### GET `/me/profile`

用途：获取比 `/auth/me` 更完整的个人资料。

响应 `data`：

```json
{
  "userId": 2,
  "username": "teacher01",
  "realName": "张老师",
  "phoneNumber": "13800000000",
  "email": "teacher@example.com",
  "avatarUrl": null,
  "organizationId": 1,
  "organizationName": "某某学院",
  "departmentId": 3,
  "departmentName": "中药教研室",
  "roleCodes": ["TEACHER"],
  "lastLoginAt": "2026-07-12T10:00:00+08:00",
  "passwordChangedAt": null,
  "mustChangePassword": false
}
```

#### PATCH `/me/profile`

允许当前用户修改：`realName`、`phoneNumber`、`email`。

禁止自行修改：账号、角色、状态、组织、部门。上述字段继续由管理员维护。

请求体：

```json
{
  "realName": "张老师",
  "phoneNumber": "13800000000",
  "email": "teacher@example.com"
}
```

#### PUT `/me/profile/avatar`

头像文件上传继续复用现有文件资源接口。设置头像时只提交已经上传的文件 ID：

```json
{
  "fileId": 123
}
```

后端必须验证文件存在、归当前用户所有、媒体类型为允许的图片类型，并生成受控的头像访问地址。禁止前端直接提交任意外部 URL 写入 `avatar_url`。

#### DELETE `/me/profile/avatar`

清除当前头像引用，不直接删除仍可能被其他业务引用的文件资源。

### 6.2 修改密码

#### PUT `/me/password`

请求体：

```json
{
  "currentPassword": "OldPassword123",
  "newPassword": "NewPassword123",
  "revokeOtherSessions": true
}
```

规则：

1. 校验当前密码。
2. 新密码至少 8 位，后续可统一提升密码强度规则。
3. 新旧密码不能相同。
4. 更新 `password_hash`、`password_changed_at`，清除 `must_change_password`。
5. 默认撤销其他会话；当前会话是否继续有效由评审项决定。
6. 审计日志只记录修改结果，不记录密码内容。

### 6.3 获取全部可见设置

#### GET `/me/settings`

响应只包含当前用户允许访问的命名空间：

```json
{
  "common": {
    "version": 1,
    "schemaVersion": 1,
    "values": {
      "defaultLandingPath": "/",
      "timezone": "Asia/Shanghai",
      "locale": "zh-CN"
    }
  },
  "appearance": {
    "version": 0,
    "schemaVersion": 1,
    "values": {
      "contentDensity": "comfortable",
      "sidebarMode": "auto",
      "reduceMotion": false
    }
  },
  "teaching": {
    "version": 0,
    "schemaVersion": 1,
    "values": {
      "defaultCourseView": "list",
      "taskReminderAdvanceMinutes": 60,
      "showStudentStatistics": true
    }
  }
}
```

不存在数据库记录时返回系统默认值，`version` 为 0。

### 6.4 获取单个设置命名空间

#### GET `/me/settings/{namespace}`

后端检查命名空间是否存在以及当前用户是否满足访问策略。无权访问返回 403，不存在返回 404。

### 6.5 保存单个设置命名空间

#### PUT `/me/settings/{namespace}`

请求体：

```json
{
  "version": 1,
  "values": {
    "contentDensity": "compact",
    "sidebarMode": "auto",
    "reduceMotion": false
  }
}
```

规则：

1. `version=0` 表示首次创建。
2. 后端根据 namespace 选择对应验证器。
3. 拒绝未知字段、错误类型和越界值。
4. 乐观锁冲突返回 HTTP 409 和业务码 `RESOURCE_CONFLICT`。
5. 返回保存后的有效值和新版本号。

### 6.6 重置单个设置命名空间

#### DELETE `/me/settings/{namespace}`

删除当前用户在该命名空间下的覆盖记录，并返回系统默认值。操作应幂等。

### 6.7 会话列表

#### GET `/me/sessions`

响应：

```json
[
  {
    "sessionId": "f4d5...",
```

### 6.8 撤销指定会话

#### DELETE `/me/sessions/{sessionId}`

只能撤销当前用户自己的会话。撤销当前会话后，当前请求成功返回，后续请求返回 401。

## 7. 登录接口调整

建议在 `LoginVO` 增加可选字段：

```json
{
  "preferredLandingPath": "/"
}
```

该字段来源于 `common.defaultLandingPath`。前端仍必须按以下优先级做最终判断：

1. 当前登录用户有权访问的 `returnUrl`。
2. 当前登录用户有权访问的 `preferredLandingPath`。
3. 拥有权限后台能力时进入 `/dashboard`。
4. 普通业务用户进入门户 `/`。
5. 第一个可访问页面或 `/profile`。

设置值不能绕过现有路由守卫。

## 8. 后端模块设计

建议新增包：

```text
com.bdis.modules.settings
├── controller
├── dto
├── entity
├── mapper
├── service
├── service.impl
├── support
└── vo
```

核心扩展接口：

```java
public interface SettingNamespaceHandler {
    String namespace();

    boolean supports(CurrentUser user);

    JsonNode defaultValues(CurrentUser user);

    JsonNode validateAndNormalize(JsonNode values, CurrentUser user);

    int schemaVersion();
}
```

核心模块负责：

- 当前用户识别。
- 命名空间处理器注册。
- 数据库存取。
- 乐观锁。
- 统一错误处理和审计。

业务模块负责：

- 自己命名空间的默认值。
- 字段白名单与校验。
- 角色或权限访问策略。
- 数据结构升级。

这样课程、采集和审核模块可以独立接入，不需要修改核心 Settings Controller。

## 10. 权限与安全设计

### 10.1 自助设置不新增普通 RBAC 权限

个人资料、密码、偏好和本人会话属于“当前用户只能操作自己的资源”，登录身份本身就是访问条件。第一期不建议为每个自助操作增加 `settings:personal:update` 等权限，避免普通账号因漏配权限而无法修改自己的设置。

### 10.2 角色分区策略

角色条件决定业务 Tab 是否出现，后端命名空间处理器必须执行相同策略。不能只在前端判断角色。

### 10.3 管理员管理他人设置

第一期不提供管理员查看或修改他人个人偏好的接口。如果后续确有客服或合规需求，再新增：

```text
settings:user:view
settings:user:reset
```

并使用独立后台接口，不复用 `/me/**`。

### 10.4 密码和会话

- 密码修改接口不得记录请求体。
- 会话表不得存储 JWT 原文。
- 修改密码后至少撤销其他会话。
- `must_change_password=1` 时，除修改密码、退出和当前用户查询外，应限制敏感业务访问。
- 可使用 `password_changed_at` 与 JWT `iat` 比较，使密码修改前签发的 Token 失效。

## 11. 错误码建议

| HTTP 状态 | 业务码                         | 场景                         |
| --------- | ------------------------------ | ---------------------------- |
| 400       | `VALIDATION_ERROR`             | 设置字段错误、密码格式错误   |
| 400       | `PASSWORD_VERIFICATION_FAILED` | 当前密码校验失败             |
| 401       | `UNAUTHORIZED`                 | Token 缺失、失效或会话已撤销 |
| 403       | `FORBIDDEN`                    | 无权访问角色专属命名空间     |
| 404       | `RESOURCE_NOT_FOUND`           | 命名空间或会话不存在         |
| 409       | `RESOURCE_CONFLICT`            | 乐观锁版本冲突               |

当前密码错误使用 HTTP 400 和独立业务码 `PASSWORD_VERIFICATION_FAILED`，避免把“已登录但密码校验失败”误判为登录会话失效。响应信息统一为“密码验证失败”，不暴露更多校验细节。

## 12. 审计设计

需要记录：

- 个人资料修改。
- 密码修改成功或失败。
- 偏好命名空间保存和重置。
- 会话撤销。

审计日志只记录命名空间、动作和结果，不记录密码或完整偏好 JSON。对于通知和界面偏好，可以记录变更字段名列表，不记录敏感值。

## 14. 测试与验收

### 14.1 后端测试

- 用户只能读取和修改自己的资料、偏好和会话。
- 未知命名空间和未知字段被拒绝。
- 教师不能写入采集或审核命名空间。
- 多角色用户可以访问对应命名空间并集。
- 乐观锁冲突返回 409。
- 修改密码后旧会话按策略失效。
- 撤销会话同时更新数据库并写 Redis 黑名单。
- 不保存或输出 JWT 原文。

### 14.2 前端测试

- 公共 Tab 对所有登录用户显示。
- 单角色与多角色 Tab 可见性正确。
- 隐藏 Tab 不能通过直接修改 URL 绕过后端校验。
- 分区独立保存、重置、失败重试和未保存提示正确。
- 默认登录页面失去权限时自动回退。
- 桌面和窄屏布局不重叠。

## 15. 明确不在本阶段实施的内容

1. `/dashboard/settings` 全局系统设置。
2. 完整通知中心、消息投递和已读状态。
3. 课程、学习、采集、审核业务字段的最终实现。
4. 移动端设置页面修改。
5. 管理员读取或修改他人个人偏好。
6. 深色主题。

## 16. 评审确认项

以下问题需要在进入实现前确认：

1. 是否接受“偏好命名空间 + JSON”的扩展模型，而不是为每类设置创建独立表？
2. 是否在第一阶段同时实现 `auth_user_session`，还是只先实现偏好与密码修改？
3. 修改密码后，当前会话继续有效还是全部会话立即失效？
4. 是否接受在 `sys_user` 增加 `password_changed_at` 和 `must_change_password`？
5. `defaultLandingPath` 是否允许用户自行选择？
6. 通知偏好第一期是否只做站内、邮件和免打扰开关，不实现实际投递？
7. 教学、学习、采集、审核 Tab 第一阶段是否只注册占位扩展点，等待对应业务负责人确认字段？

## 17. 推荐评审结论

建议批准以下范围进入第一阶段实现：

1. 新增 `sys_user_preference` 和 `auth_user_session` 两张表。
2. 为 `sys_user` 增加两个密码安全字段。
3. 实现个人资料、修改密码、偏好和会话接口。
4. 实现统一 `/settings` 页面和公共设置分区。
5. 角色专属 Tab 先完成注册与访问控制，只实现已经由对应业务负责人确认的字段。

该方案能满足当前个人设置需求，同时避免按角色复制页面、在用户表堆积字段或提前侵入课程和移动端模块。
