# 生物医药数字信息系统技术栈详细设计规范

## 1. 文档定位

本文档用于明确生物医药数字信息系统的详细技术栈选型，作为后续系统设计、开发实施、环境搭建、接口联调、部署交付和维护升级的技术依据。

本文档仅规定技术栈和工程化边界，不展开业务功能设计、数据库表结构、接口字段、页面原型和具体业务流程。

## 2. 总体技术路线

系统采用前后端分离架构。

- 前端采用 Next.js + TypeScript 构建 Web 管理端和查询端。
- 后端采用 Spring Boot 构建 REST API、SOAP 对接适配、鉴权、业务服务和数据访问服务。
- 数据库采用 MySQL 8.0.x。
- 缓存采用 Redis。
- 前后端主通信方式采用 RESTful API。
- 与校内系统的数据交换采用 SOAP 协议，并在后端通过独立适配层进行封装。
- 初版采用单体后端架构，后续可根据访问量、文件处理量和集成复杂度演进。
- 部署采用 Docker Compose + nginx 的方式进行统一编排和反向代理。

## 3. 版本与运行环境约定

| 类别 | 技术规定 | 说明 |
| --- | --- | --- |
| 前端运行时 | Node.js LTS | 使用项目启动时稳定的 LTS 版本，保证 Next.js 生态兼容性。 |
| 后端运行时 | Java 21 LTS | 使用 Java 21 作为后端统一运行时和编译基线。 |
| 数据库 | MySQL 8.0.x | 作为核心业务数据存储。 |
| 缓存 | Redis | 用于缓存、临时状态、验证码、权限相关缓存等。 |
| 开发操作系统 | 不做限制 | 开发人员可使用 Windows、macOS 或 Linux，本地开发环境不作强制限制。 |
| 生产部署操作系统 | Linux | 测试和生产部署以 Linux 环境为主。 |
| 容器化 | Docker + Docker Compose | 用于统一编排前端、后端、MySQL、Redis、nginx 等服务。 |

版本锁定原则：

- 大版本应在项目启动阶段统一锁定。
- 小版本和补丁版本可根据安全修复、兼容性和测试结果升级。
- 生产环境不直接使用未经验证的新版本依赖。

## 4. 前端技术栈详细规定

### 4.1 基础框架

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| 开发语言 | TypeScript | 提升类型约束、接口联调可靠性和代码可维护性。 |
| 前端框架 | Next.js | 用于构建 React 应用、路由、页面布局和构建发布。 |
| 路由模式 | Next.js App Router | 采用新式 App Router，支持布局嵌套、路由分组和服务端能力扩展。 |
| 渲染方式 | CSR + SSR 混合 | 后台管理以 CSR 为主，公开查询、地图展示等页面可按需使用 SSR。 |
| 包管理器 | pnpm | 安装速度快、磁盘占用低，适合工程化项目。 |
| 打包工具 | Next.js 内置构建工具 | 不单独引入 Vite/Webpack 配置，降低构建复杂度。 |

### 4.2 页面与状态管理

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| UI 组件库 | Ant Design | 适合后台管理系统，表格、表单、弹窗、布局、权限菜单等组件成熟。 |
| 样式方案 | Ant Design Theme + CSS Modules | 通过 Ant Design 主题统一视觉风格，局部样式使用 CSS Modules 管理。 |
| 全局状态管理 | Zustand | 用于用户信息、权限菜单、全局 UI 状态、轻量业务状态管理。 |
| 服务端数据缓存 | TanStack Query | 用于列表、分页、详情、缓存刷新、加载状态和错误状态管理。 |
| 表单方案 | Ant Design Form | 与 Ant Design 组件配套，适合复杂业务表单和校验反馈。 |

### 4.3 接口请求与鉴权

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| HTTP 请求库 | Axios | 统一封装请求实例、token 注入、错误处理和响应拦截。 |
| 前端鉴权 | JWT + 路由守卫 + Axios 拦截器 | 通过 token 识别用户身份，通过路由守卫控制页面访问，通过拦截器处理鉴权失败。 |
| 接口数据格式 | JSON | 前后端 REST API 统一使用 JSON 作为主要数据交换格式。 |
| 环境变量 | Next.js `.env` 系列文件 | 区分开发、测试、生产环境的 API 地址、地图配置和运行参数。 |

### 4.4 地图与可视化

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| 初版地图方案 | Leaflet + 地图数据 | 用于中药材分布网络地图初版设计，适合轻量地图展示和点位分布查询。 |
| 地图数据来源 | 自有数据或可用公开地图数据 | 结合重庆市中药材分布数据进行展示，具体数据源在数据设计阶段确定。 |
| 后期可视化升级 | ECharts | 作为统计图表、趋势分析、数据看板和复杂可视化的后期升级方向。 |

### 4.5 前端代码质量

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| 代码检查 | ESLint | 检查 TypeScript、React、Next.js 代码规范问题。 |
| 代码格式化 | Prettier | 统一代码格式，减少风格差异。 |
| 提交前检查 | lint-staged | 在提交前对变更文件执行检查和格式化。 |
| 前端测试 | Vitest + React Testing Library，预留 | 初版不强制引入，后期可用于组件、hooks、工具函数测试。 |

## 5. 后端技术栈详细规定

### 5.1 基础框架

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| 开发语言 | Java 21 | 后端统一采用 Java 21 LTS。 |
| 后端框架 | Spring Boot | 作为后端主框架，负责 Web、配置、依赖装配和服务启动。 |
| Web 框架 | Spring MVC | 采用传统 Servlet Web 模式，稳定、成熟，适合 REST API。 |
| 构建工具 | Maven | 用于依赖管理、编译、测试、打包和插件集成。 |
| 接口风格 | REST + SOAP Adapter | 主体业务接口采用 RESTful API；校内系统对接使用 SOAP 适配层。 |

### 5.2 鉴权与权限控制

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| 鉴权框架 | Spring Security + JWT | 使用 Spring Security 处理认证与授权，通过 JWT 支持前端和移动端访问。 |
| 权限模型 | RBAC + 数据权限 | 支持用户、角色、权限、层级范围和业务数据范围控制。 |
| Token 管理 | JWT + Redis 辅助 | JWT 用于身份传递，Redis 可用于 token 黑名单、登录状态和权限缓存。 |
| 接口访问控制 | Spring Security Filter Chain | 对不同接口路径、角色权限和登录状态进行统一控制。 |

### 5.3 数据访问

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| ORM 框架 | MyBatis-Plus | 提供基础 CRUD、分页、条件构造和常用数据访问能力。 |
| SQL 扩展 | MyBatis XML | 对复杂查询、统计报表、权限过滤查询使用 XML 编写 SQL。 |
| 数据库 | MySQL 8.0.x | 存储用户、权限、资源、生长数据、教学科研、培训、评价、业绩和日志等数据。 |
| 连接池 | HikariCP | Spring Boot 默认连接池，性能稳定。 |
| 数据库版本管理 | Flyway | 对数据库建表脚本、结构变更脚本进行版本化管理。 |
| 对象转换 | MapStruct | 用于 Entity、DTO、VO 之间转换，减少手写转换代码。 |

### 5.4 SOAP 集成

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| SOAP 框架 | Apache CXF | 用于与校内 SOAP 系统进行服务调用或服务暴露。 |
| 集成方式 | 独立适配层 | 将 SOAP 细节封装在后端集成模块中，避免污染核心业务接口。 |
| 内部接口 | REST API | 前端、APP 和管理端仍主要调用 REST API。 |
| 交换日志 | 业务日志 + 审计日志 | 记录 SOAP 请求、响应、结果状态和异常信息。 |

### 5.5 缓存与任务

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| 缓存 | Redis | 用于登录状态辅助、权限缓存、验证码、字典缓存、热点查询缓存等。 |
| 定时任务 | Spring Task | 初版用于自动备份、定时统计、状态维护等简单任务。 |
| 任务升级方向 | Quartz 或 XXL-JOB | 后期如任务复杂、需要可视化调度或分布式调度时再升级。 |
| 消息队列 | 初版暂不引入 | 当前阶段避免增加复杂度。 |
| 消息队列升级方向 | RabbitMQ | 后期可用于异步通知、文件处理、备份任务、日志解耦等场景。 |

### 5.6 文件存储

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| 初版文件存储 | 本地磁盘 + 数据库索引 | 初版用于课件、视频、图谱、附件、申报材料等文件存储。 |
| 文件元数据 | MySQL | 记录文件名称、类型、大小、业务归属、上传人、上传时间、访问权限等元数据。 |
| 后期升级方向 | MinIO | 后期如文件数量、视频体量或多节点部署需求增加，可升级为对象存储。 |

### 5.7 后端接口与文档

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| 接口文档 | Knife4j / SpringDoc OpenAPI | 生成 REST API 文档，便于前后端联调和测试。 |
| 参数校验 | Jakarta Validation | 对请求 DTO 进行必填、长度、格式、范围等校验。 |
| JSON 序列化 | Jackson | Spring Boot 默认 JSON 处理方案。 |
| 全局异常处理 | Spring `@RestControllerAdvice` | 统一处理参数错误、鉴权失败、业务异常和系统异常。 |
| 统一返回结构 | 统一响应体 | REST API 使用统一响应结构，便于前端处理成功、失败和异常状态。 |

### 5.8 后端日志与审计

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| 日志门面 | SLF4J | Java 日志统一门面。 |
| 日志实现 | Logback | Spring Boot 默认日志实现，成熟稳定。 |
| 操作审计 | Spring AOP | 对登录、上传、下载、审核、导出、删除、SOAP 交换等关键操作记录审计日志。 |
| 后端代码规范 | Checkstyle + Spotless | Checkstyle 做规范检查，Spotless 做自动格式化。 |
| 后端静态分析 | SpotBugs，后期增强 | 初版不强制引入，后期用于发现潜在空指针、资源泄露和错误用法。 |
| 后端测试 | JUnit 5 + Mockito + Spring Boot Test | 用于服务层、接口层、权限逻辑和数据访问逻辑测试。 |

## 6. 数据库与命名规范

| 模块 | 技术规定 | 说明 |
| --- | --- | --- |
| 数据库类型 | MySQL 8.0.x | 统一作为关系型数据库。 |
| 表字段命名 | snake_case | 表名、字段名使用小写字母加下划线。 |

| 时间字段 | 统一使用创建时间、更新时间 | 重要业务表保留创建和更新时间字段。 |
| 审计字段 | 重要表保留创建人、更新人 | 便于追踪数据来源和修改责任。 |

## 10. 结论

本系统详细技术栈采用成熟、稳定、工程化成本适中的组合：

- 前端以 Next.js、TypeScript、Ant Design、Zustand、TanStack Query 和 Axios 为核心。
- 后端以 Java 21、Spring Boot、Spring MVC、Spring Security、MyBatis-Plus 和 Apache CXF 为核心。
- 数据层以 MySQL 8.0.x、Redis、Flyway 和 HikariCP 为基础。
- 工程化以 pnpm、Maven、ESLint、Prettier、Checkstyle、Spotless、Docker Compose 和 nginx 为支撑。

该技术栈适合当前系统的后台管理、数据采集、校内 SOAP 集成、地图查询、文件管理、权限控制和数据统计需求，同时保留了文件存储、任务调度、消息队列、可视化和静态分析等后期升级空间。
