# 批次档案与采集任务模块接口文档

> 版本：V1.0
> 日期：2026-07-10
> 适用范围：PC 端与移动端的采集任务、批次档案、图片绑定和识别汇总接口。

## 1. 模块说明

批次档案与采集任务模块用于管理中药材采集业务中的“任务”和“批次”。

核心数据对象：

- `herb_collection_task`：采集任务，用于记录管理员或老师下发的采集任务。
- `herb_batch`：批次档案，用于记录某一批中药材采集或生产批次。
- `herb_batch_image`：批次与采集图片关联，用于记录批次下绑定的采集图片。

接口统一返回 `Result<T>` 结构。当前项目配置了 `server.servlet.context-path=/api`，因此 Controller 中的 `/herb/...` 和 `/mobile/herb/...` 对外访问路径分别是 `/api/herb/...` 和 `/api/mobile/herb/...`。

## 2. 业务流程

```text
PC 端创建采集任务
        ↓
采集人员手机端查看任务
        ↓
在任务下创建批次
        ↓
手机端拍照上传图片
        ↓
图片保存到 herb_image
        ↓
图片绑定到 herb_batch_image
        ↓
图片执行图谱识别，生成 herb_identification_result
        ↓
批次汇总多张图片识别结果
        ↓
生成批次最终药材、质量等级、评价摘要
        ↓
PC 端确认、归档
```

## 3. 数据表说明

### 3.1 `herb_collection_task`

核心字段：

```text

task_name
species_id

collect_place

```

批次档案主表，用于记录某一批中药材采集或生产批次。

核心字段：

```text
batch_code
batch_name
task_id
species_id
species_name
origin_place

identified_count
reviewed_count
need_review_count
final_species_id
final_species_name

```

## 4. 状态说明

### 4.1 采集任务状态 `task_status`

| 状态值 | 中文含义 |
| --- | --- |
| `draft` | 草稿 |
| `published` | 已发布 |
| `in_progress` | 进行中 |
| `completed` | 已完成 |
| `cancelled` | 已取消 |

状态流转：

```text
draft -> published
published -> in_progress
in_progress -> completed
draft / published / in_progress -> cancelled
```

### 4.2 批次状态 `batch_status`

| 状态值 | 中文含义 |
| --- | --- |
| `draft` | 草稿 |
| `collecting` | 采集中 |
| `submitted` | 已提交 |
| `identifying` | 识别中 |
| `reviewing` | 复核中 |
| `confirmed` | 已确认 |
| `archived` | 已归档 |
| `cancelled` | 已取消 |

状态流转：

```text
draft -> collecting
collecting -> submitted
submitted -> identifying
identifying -> reviewing / confirmed
reviewing -> confirmed
confirmed -> archived
confirmed -> reviewing
draft / collecting / submitted / identifying / reviewing / confirmed -> cancelled
```

### 4.3 批次图片绑定状态 `bind_status`

| 状态值 | 中文含义 |
| --- | --- |
| `bound` | 已绑定 |
| `removed` | 已移除 |

### 4.4 图片角色 `image_role`

| 状态值 | 中文含义 |
| --- | --- |
| `leaf` | 叶片 |
| `root` | 根部 |
| `stem` | 茎 |
| `flower` | 花 |
| `fruit` | 果实 |
| `whole_plant` | 整株 |
| `medicinal_part` | 药用部位 |
| `environment` | 生长环境 |
| `other` | 其他 |

### 4.5 批次质量等级 `quality_level`

| 状态值 | 中文含义 |
| --- | --- |
| `excellent` | 优秀 |
| `good` | 良好 |
| `normal` | 一般 |
| `poor` | 较差 |
| `unknown` | 未知 |

## 7. 与图谱识别模块的关系

批次模块不重新实现图谱识别，而是复用图谱识别模块已有能力。

相关表关系：

```text
herb_batch
    ↓
herb_batch_image
    ↓
herb_image
    ↓
herb_identification_result
```

单张图片的识别结果来自 `herb_identification_result`。批次汇总逻辑基于批次下所有绑定图片的最终识别结论。

批次质量评价主要参考：

```text
image_count
identified_count
reviewed_count
need_review_count
final_confidence 平均值
识别结果一致性
人工复核状态
```

## 10. 注意事项

1. `archived` 和 `cancelled` 批次不允许继续绑定图片、解绑图片、刷新汇总、修改评价或提交。
2. 手机端上传图片会复用图片上传服务，图片先写入 `herb_image`，再写入 `herb_batch_image`。
3. 手机端上传默认不自动识别；显式传入 `autoIdentify=true` 时会在上传绑定后触发统一识别。同步识别失败只作为最佳努力结果返回，默认流程应通过上传后的手动/批量识别避免破坏上传成功语义。
4. 批次汇总评价基于已绑定图片的最终识别结果，建议在批量识别或人工复核后刷新。
5. PC 端 `/api/herb/batch/{batchId}/identify-missing-images` 当前暂未实现；手机端 `/api/mobile/herb/batches/{batchId}/identify-missing-images` 已实现。
6. 文档 curl 示例使用的是简短联调命令，不是完整自动化测试脚本。
