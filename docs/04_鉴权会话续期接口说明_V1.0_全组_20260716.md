# 生物医药数字信息系统鉴权会话续期接口说明

> 版本：V1.0
> 日期：2026-07-16
> 负责人：全组
> 适用范围：Web、移动端及使用 `/api/auth` 的客户端会话续期。

## 1. 文档定位

本文档是《用户鉴权模块前后端接口与后端接入说明》的增量补充。登录、初始化管理员、当前用户和权限基础约定仍以原说明为准；本文件覆盖 access token 与 refresh token 的返回字段、刷新接口和客户端重试规则。

## 2. 鉴权接口

- `POST /api/auth/sessions` 登录成功后返回 `accessToken`、`refreshToken`、`expiresIn`、`refreshExpiresIn`、`tokenType` 和用户信息。
- `accessToken` 默认有效期为 1440 分钟。
- `refreshToken` 默认有效期为 7 天。
- `POST /api/auth/sessions/refresh` 使用 refresh token 换取新的 access token 和 refresh token。
- Refresh token 每次刷新成功后都会轮换，旧 refresh token 立即失效。
- 登录接口和 refresh 接口本身不得触发自动刷新。
- 普通业务接口返回 401 时，客户端应先刷新 token 并重放原请求；refresh 明确返回 401 或没有 refresh token 时，才清理本地会话并跳转登录。
- `DELETE /api/auth/sessions/current` 在 access token 过期后可以先刷新再调用，以确保服务端 refresh 会话被撤销。

### 2.1 刷新会话请求

`POST /api/auth/sessions/refresh` 不携带旧 access token；请求体只传当前 refresh token：

```json
{
  "refreshToken": "<refresh-token>"
}
```

成功响应与登录响应使用相同的 `LoginVO` 结构。客户端必须用响应中的两个 token 原子替换本地旧值，不能继续保存旧 refresh token：

```json
{
  "accessToken": "<jwt-access-token>",
  "refreshToken": "<rotated-refresh-token>",
  "tokenType": "Bearer",
  "expiresIn": 86400,
  "refreshExpiresIn": 604800,
  "user": {},
  "preferredLandingPath": "/dashboard",
  "mustChangePassword": false
}
```

`expiresIn` 与 `refreshExpiresIn` 均以秒为单位。示例值来自默认配置，实际值由 `BDIS_JWT_ACCESS_TOKEN_TTL_MINUTES` 和 `BDIS_JWT_REFRESH_TOKEN_TTL_DAYS` 决定。

### 2.2 客户端处理规则

1. Web 与移动端对普通业务请求收到 401 时，只发起一次共享的刷新请求；并发失败请求等待同一刷新结果后重放。
2. 登录、刷新、初始化管理员等鉴权接口不得触发自动刷新，避免循环请求。
3. 刷新失败、refresh token 缺失或重放后仍为 401 时，清理本地会话并跳转登录页。
4. 403 表示已登录但无权限，不得被当作 token 失效处理。

## 3. 会话表字段

`auth_user_session` 新增字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `refresh_token_hash` | `CHAR(64)` | Refresh Token 的 SHA-256 哈希，不保存原文 |
| `refresh_expires_at` | `DATETIME` | Refresh Token 到期时间 |

新增索引：

```text
UNIQUE KEY uk_auth_user_session_refresh_token_hash (refresh_token_hash)
KEY idx_auth_user_session_refresh_expires_at (refresh_expires_at)
```

## 4. 生命周期规则

- `expires_at` 表示 access token 到期时间。
- `refresh_expires_at` 表示完整登录会话可刷新的到期时间。
- 新数据应按 `refresh_expires_at` 判断会话是否过期；历史无 refresh 字段的数据才回退到 `expires_at`。
- Refresh token 轮换必须使用旧哈希作为更新条件，避免同一个旧 token 被并发重复消费。

## 5. 安全边界与后续事项

当前 Web 与移动端按项目既有方案把 refresh token 存放在本地存储。该方案会扩大 XSS 后的凭据有效期，后续应评估迁移到 HttpOnly Cookie 或 BFF 模式。服务端只保存 refresh token 的 SHA-256 哈希；刷新成功即轮换旧 token，并由会话状态与到期时间共同限制其使用。
