# 生物医药数字信息系统 文档命名规范（简化版）

适用于 4 人小组、12 天左右实训周期的项目文档协作管理。

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 生物医药数字信息系统 |
| 适用范围 | 小组实训项目文档、答辩材料、设计资料、测试部署资料 |
| 命名目标 | 便于查找、排序、区分版本和明确负责人 |
| 推荐格式 | 编号_文档名称_V版本号_负责人_日期 |

## 一、命名原则

1. 能看懂：看到文件名就知道是什么文档。
2. 能排序：通过编号让文档按阶段自然排列。
3. 能区分版本：避免“最终版”“最终最终版”等混乱命名。
4. 能追责：文件名中保留主要负责人。
5. 不过度复杂：适合短周期实训项目，不采用企业级繁琐命名。

## 二、统一命名格式

本项目所有正式文档统一采用以下格式：

```text
编号_文档名称_V版本号_负责人_日期
```

说明：

| 组成部分 | 说明 |
| --- | --- |
| 编号 | 用于区分文档类别，例如 01、02、03。 |
| 文档名称 | 说明文件内容，例如 需求分析说明书、模块设计说明书。 |
| V版本号 | 表示当前文档版本，例如 V0.5、V1.0、V1.1。 |
| 负责人 | 填写主要维护人员姓名；多人共同维护可写“全组”。 |
| 日期 | 使用 YYYYMMDD 格式，例如 20260707。 |

## 三、文档编号建议

| 编号 | 文档类型 |
| --- | --- |
| 01 | 项目计划书 |
| 02 | 需求分析说明书 |
| 03 | 模块设计说明书 |
| 04 | 接口设计说明书 |
| 05 | 数据库设计说明书 |
| 06 | 测试文档 |
| 07 | 部署文档 |
| 08 | 答辩材料 |
| 09 | 项目总结 |
| 10 | 其他资料 |

## 四、版本号规则

| 版本号 | 含义 |
| --- | --- |
| V0.1 | 初稿，内容尚不完整。 |
| V0.5 | 基本完成，等待小组修改。 |
| V1.0 | 正式提交版。 |
| V1.1 | 小修改版，例如修正错字、补充少量内容。 |
| V2.0 | 大改版，例如结构调整或内容大幅修改。 |

推荐命名：

```text
01_项目计划书_V1.0_全组_20260707.docx
02_需求分析说明书_V1.0_李四_20260707.docx
03_模块设计说明书_V1.0_王五_20260708.docx
04_接口设计说明书_V1.0_赵六_20260708.docx

07_部署说明书_V1.0_张三_20260711.docx
08_答辩PPT_V1.0_全组_20260712.pptx
```

不推荐命名：

```text
需求.docx
接口最新版.docx
模块设计最终版.docx
最终最终版.docx
老师看这个.docx
新建 Microsoft Word 文档.docx
```

## 六、文件夹结构建议

文档统一放入 docs 文件夹。为了减少管理成本，建议只分为以下几类：

```text
docs
├── 正式文档
├── 答辩材料
├── 历史版本
└── 临时资料
```

说明：正式文档保存最终需要提交或展示的文档；答辩材料保存 PPT、答辩稿、演示脚本；历史版本保存被替换的旧版本；临时资料保存截图、参考资料和未整理素材。

## 七、团队协作要求

1. 提交文档前必须按统一格式命名。
2. 修改已有正式文档时，不直接覆盖原文件，应复制后提升版本号。
3. 草稿和临时资料放入“临时资料”，正式版放入“正式文档”。
4. 最终提交时，每类文档只保留最新版，旧版本统一移入“历史版本”。
5. 负责人字段填写主要维护人；多人共同维护时填写“全组”。

## 八、可直接写入项目管理文档的说明

本项目采用简化文档命名规范，统一格式为“编号_文档名称_V版本号_负责人_日期”。其中，编号用于区分文档类型，文档名称用于说明文件内容，版本号用于标识文档修改阶段，负责人用于明确主要维护人员，日期用于判断文档更新时间。所有成员提交文档时应使用统一命名格式，避免使用“最终版”“最新版”“修改版”等模糊名称。通过统一命名规范，可以提高小组文档管理效率，方便后续查找、修改、归档和提交。
