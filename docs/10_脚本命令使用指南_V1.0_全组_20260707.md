# BDIS 脚本命令使用指南

本文档说明项目初始化阶段可使用的统一命令。所有命令均在项目根目录执行，面向 Windows、Linux 等不同开发环境，主要用于环境初始化、工具检查、构建验证、数据库迁移和生成物清理。

## 一、使用前提

本项目使用 `pnpm` 统一执行脚本。首次拉取项目后，建议按以下顺序操作：

```bash
pnpm install
pnpm setup
pnpm check
pnpm validate
```

其中 `.env` 和 `frontend/.env.local` 是本地个人配置文件，不应提交到 Git。

数据库迁移操作必须先阅读 [10_Flyway数据库迁移规则_V1.0_全组_20260708.md](10_Flyway数据库迁移规则_V1.0_全组_20260708.md)。项目数据库以 MySQL 8.0.x 为准。

## 二、常用命令

| 命令                  | 作用                  | 说明                                                                                                       |
| --------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------- |
| `pnpm setup`          | 初始化本地环境配置    | 从 `.env.example` 生成 `.env`，从 `frontend/.env.example` 生成 `frontend/.env.local`；已有文件不会被覆盖。 |
| `pnpm check`          | 检查本机开发工具      | 检查 Node.js、pnpm、Java 21、Maven、Docker、Docker Compose 是否可用。                                      |
| `pnpm validate`       | 一键验证项目状态      | 依次执行前端 lint、前端 build、后端 test、Docker Compose 配置检查。                                        |
| `pnpm clean`          | 清理生成物            | 删除 `frontend/.next`、`frontend/out`、`frontend/coverage`、`backend/target`、`flyway/target`。            |
| `pnpm dev`            | 启动前端开发服务      | 等同于 `pnpm dev:web`。                                                                                    |
| `pnpm dev:web`        | 启动前端              | 运行 Next.js 开发服务。                                                                                    |
| `pnpm dev:mobile`     | 启动手机端 H5         | 运行 mobile 模块的 uni-app H5 开发服务。                                                                   |
| `pnpm dev:api`        | 启动后端              | 使用 Maven 运行 Spring Boot 后端。                                                                         |
| `pnpm dev:infra`      | 启动基础设施          | 通过 Docker Compose 启动 MySQL 和 Redis。                                                                  |
| `pnpm db:info`        | 查看数据库迁移状态    | 通过独立 `flyway` 模块执行，不启动后端服务。                                                               |
| `pnpm db:migrate`     | 执行数据库迁移        | 根据 `backend/src/main/resources/db/migration` 中的 migration 更新数据库。                                 |
| `pnpm db:validate`    | 校验数据库迁移状态    | 校验 migration 文件与数据库记录是否一致。                                                                  |
| `pnpm db:repair`      | 修复 Flyway 元数据    | 仅在确认原因后使用，不用于掩盖脚本不一致问题。                                                             |
| `pnpm db:clean:local` | 清空本地开发库对象    | 只允许本地 `_dev` 数据库使用，禁止用于共享库、测试库和生产库。                                             |
| `pnpm build`          | 构建前端              | 等同于 `pnpm build:web`。                                                                                  |
| `pnpm build:mobile:h5` | 构建手机端 H5        | 构建 mobile 模块的 uni-app H5 产物。                                                                       |
| `pnpm lint`           | 检查前端代码          | 等同于 `pnpm lint:web`。                                                                                   |
| `pnpm format`         | 格式化前端代码        | 等同于 `pnpm format:web`。                                                                                 |
| `pnpm test`           | 运行后端测试          | 等同于 `pnpm test:api`。                                                                                   |
| `pnpm compose:config` | 检查 Compose 配置     | 不启动容器，只验证 `docker-compose.yml` 配置是否有效。                                                     |
| `pnpm compose:up`     | 启动完整 Compose 服务 | 构建并启动 MySQL、Redis、后端、前端、nginx。                                                               |
| `pnpm compose:down`   | 停止 Compose 服务     | 停止并移除 Compose 创建的容器网络。                                                                        |

## 三、推荐工作流

### 1. 新成员首次初始化

```bash
pnpm install
pnpm setup
pnpm check
```

执行 `pnpm setup` 后，需要根据个人本机环境修改 `.env` 和 `frontend/.env.local`，例如数据库用户名、密码、Redis 密码、前端 API 地址等。

### 2. 日常前端开发

```bash
pnpm dev
```

如需明确启动前端，也可以使用：

```bash
pnpm dev:web
```

### 3. 日常后端开发

先启动 MySQL 和 Redis：

```bash
pnpm dev:infra
```

再启动后端：

```bash
pnpm dev:api
```

### 4. 手机端开发

```bash
pnpm dev:mobile
```

构建手机端 H5：

```bash
pnpm build:mobile:h5
```

### 5. AI 识别服务开发

AI 服务使用 Python 虚拟环境运行，`ARK_API_KEY` 属于本地密钥，不得写入 Git 仓库。

```bash
cd ai_service
uvicorn recognize_app:app --host 0.0.0.0 --port 8001
```

另开终端启动特征提取服务：

```bash
cd ai_service
uvicorn feature_app:app --host 0.0.0.0 --port 8002
```

### 6. 数据库迁移

当前仓库已经接入独立 `flyway` 模块，根目录 `pnpm db:*` 命令会通过 Maven Flyway 插件执行数据库迁移，不启动后端服务。

迁移脚本目录为：

```text
backend/src/main/resources/db/migration
```

数据库连接参数读取顺序：

1. 当前 shell 环境变量。
2. 项目根目录 `.env`。
3. 脚本内默认值。

默认值如下：

| 变量             | 默认值       |
| ---------------- | ------------ |
| `MYSQL_HOST`     | `localhost`  |
| `MYSQL_PORT`     | `3306`       |
| `MYSQL_DATABASE` | `biomed_dev` |
| `MYSQL_USER`     | `bdis`       |
| `MYSQL_PASSWORD` | `change-me`  |

本地执行数据库迁移前，先启动 MySQL 和 Redis：

```bash
pnpm dev:infra
```

查看迁移状态：

```bash
pnpm db:info
```

执行迁移：

```bash
pnpm db:migrate
```

校验迁移状态：

```bash
pnpm db:validate
```

修复 Flyway 元数据：

```bash
pnpm db:repair
```

清空本地开发库对象：

```bash
pnpm db:clean:local
```

说明：

1. `pnpm db:clean:local` 仅允许连接 `localhost`、`127.0.0.1`、`::1`，且数据库名必须以 `_dev` 结尾。
2. 若目录下没有 migration 文件，`pnpm db:migrate` 不会初始化业务表。
3. 共享开发库、测试库和生产库不得使用 `clean`。
4. 迁移失败时先查看错误日志，不得直接修改已执行过的历史 migration。
5. `pnpm db:repair` 只用于修复 Flyway 元数据，使用前应先确认失败原因。

后端配置中仍保留 Spring Boot Flyway 开关，默认关闭自动迁移：

```yaml
spring:
  flyway:
    enabled: ${FLYWAY_ENABLED:false}
```

数据库初始化推荐流程：

```bash
pnpm dev:infra
pnpm db:info
pnpm db:migrate
pnpm db:validate
pnpm dev:api
```

### 7. 提交前检查

```bash
pnpm validate
```

该命令会执行前端检查、前端构建、后端测试和 Docker Compose 配置检查。若该命令失败，应先修复失败项再提交代码。

### 8. 清理构建生成物

```bash
pnpm clean
```

该命令只清理前端、后端和 Flyway 模块生成物，不删除 `node_modules`、数据库数据卷、`.env` 或业务文件。

## 四、数据库迁移注意事项

1. 数据库以 MySQL 8.0.x 为准，迁移脚本不得按其他数据库方言编写。
2. Flyway migration 是数据库结构变更的唯一正式来源。
3. 已合并并执行过的 migration 不得修改、重命名或删除。
4. 测试数据、演示数据和个人账号不得写入正式 migration。
5. 必要字典数据应单独放入字典初始化 migration。
6. 后端 Flyway 默认关闭，常规迁移使用 `pnpm db:*` 命令执行。
7. `pnpm db:clean:local` 只允许本地开发库使用，不得用于共享库、测试库和生产库。

## 五、注意事项

1. 不要提交 `.env`、`frontend/.env.local`、构建产物、日志、缓存和本地 IDE 配置。
2. `pnpm setup` 不会覆盖已有本地配置，避免误删个人数据库账号和密码。
3. 后端脚本要求 Java 21。若本机默认 Java 不是 21，脚本会优先使用 `JAVA_HOME` 指向的 Java 21；在 Arch Linux 上也会尝试使用 `/usr/lib/jvm/java-21-openjdk`。
4. `pnpm validate` 依赖本机已有 Java、Maven、Docker 等工具；如果失败，先执行 `pnpm check` 查看缺失项。
5. 当前脚本只服务项目初始化和工程协作，不生成业务类、接口字段或测试数据。
6. 数据库表结构由已确认的数据库设计和 Flyway migration 共同维护，不通过普通脚本临时生成。
7. 后续如小组确定接口设计和模块职责，可在本指南基础上补充接口文档生成等脚本。
