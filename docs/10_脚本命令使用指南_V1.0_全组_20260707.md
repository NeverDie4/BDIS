# BDIS 脚本命令使用指南

本文档说明项目初始化阶段可使用的统一命令。所有命令均在项目根目录执行，面向 Windows、Linux 等不同开发环境，主要用于环境初始化、工具检查、构建验证和生成物清理。

## 一、使用前提

本项目使用 `pnpm` 统一执行脚本。首次拉取项目后，建议按以下顺序操作：

```bash
pnpm install
pnpm setup
pnpm check
pnpm validate
```

其中 `.env` 和 `frontend/.env.local` 是本地个人配置文件，不应提交到 Git。

## 二、常用命令

| 命令 | 作用 | 说明 |
| --- | --- | --- |
| `pnpm setup` | 初始化本地环境配置 | 从 `.env.example` 生成 `.env`，从 `frontend/.env.example` 生成 `frontend/.env.local`；已有文件不会被覆盖。 |
| `pnpm check` | 检查本机开发工具 | 检查 Node.js、pnpm、Java 21、Maven、Docker、Docker Compose 是否可用。 |
| `pnpm validate` | 一键验证项目状态 | 依次执行前端 lint、前端 build、后端 test、Docker Compose 配置检查。 |
| `pnpm clean` | 清理生成物 | 删除 `frontend/.next`、`frontend/out`、`frontend/coverage`、`backend/target`。 |
| `pnpm dev` | 启动前端开发服务 | 等同于 `pnpm dev:web`。 |
| `pnpm dev:web` | 启动前端 | 运行 Next.js 开发服务。 |
| `pnpm dev:mobile` | 启动手机端 H5 开发服务 | 运行 mobile 模块的 uni-app H5 开发服务。 |
| `pnpm dev:api` | 启动后端 | 使用 Maven 运行 Spring Boot 后端。 |
| `pnpm dev:infra` | 启动基础设施 | 通过 Docker Compose 启动 MySQL 和 Redis。 |
| `pnpm build` | 构建前端 | 等同于 `pnpm build:web`。 |
| `pnpm lint` | 检查前端代码 | 等同于 `pnpm lint:web`。 |
| `pnpm format` | 格式化前端代码 | 等同于 `pnpm format:web`。 |
| `pnpm test` | 运行后端测试 | 等同于 `pnpm test:api`。 |
| `pnpm compose:config` | 检查 Compose 配置 | 不启动容器，只验证 `docker-compose.yml` 配置是否有效。 |
| `pnpm compose:up` | 启动完整 Compose 服务 | 构建并启动 MySQL、Redis、后端、前端、nginx。 |
| `pnpm compose:down` | 停止 Compose 服务 | 停止并移除 Compose 创建的容器网络。 |

## 三、推荐工作流

### 1. 新成员首次初始化

```bash
pnpm install
pnpm setup
pnpm check
```

执行 `pnpm setup` 后，需要根据个人本机环境修改 `.env` 和 `frontend/.env.local`，例如数据库用户名、密码、Redis 密码、前端 API 地址等。

### 2. 日常前端开发

```bash
pnpm dev
```

如需明确启动前端，也可以使用：

```bash
pnpm dev:web
```

### 3. 日常后端开发

先启动 MySQL 和 Redis：

```bash
pnpm dev:infra
```

再启动后端：

```bash
pnpm dev:api
```

### 4. 手机端开发

```bash
pnpm dev:mobile
```

### 5. AI 识别服务开发

以下命令在 PowerShell 中执行。`ARK_API_KEY` 属于本地密钥，不要写入 Git 仓库；请替换为个人本机环境中的有效密钥。

```powershell
cd ai_service
$env:ARK_API_KEY = "<your-ark-api-key>"
uvicorn recognize_app:app --host 0.0.0.0 --port 8001
```

另开一个 PowerShell 终端启动特征提取服务：

```powershell
cd ai_service
uvicorn feature_app:app --host 0.0.0.0 --port 8002
```

### 6. 提交前检查

```bash
pnpm validate
```

该命令会执行前端检查、前端构建、后端测试和 Docker Compose 配置检查。若该命令失败，应先修复失败项再提交代码。

### 7. 清理构建生成物

```bash
pnpm clean
```

该命令只清理前后端构建产物，不删除 `node_modules`、数据库数据卷、`.env` 或业务文件。

## 四、注意事项

1. 不要提交 `.env`、`frontend/.env.local`、构建产物、日志、缓存和本地 IDE 配置。
2. `pnpm setup` 不会覆盖已有本地配置，避免误删个人数据库账号和密码。
3. 后端脚本要求 Java 21。若本机默认 Java 不是 21，脚本会优先使用 `JAVA_HOME` 指向的 Java 21；在 Arch Linux 上也会尝试使用 `/usr/lib/jvm/java-21-openjdk`。
4. `pnpm validate` 依赖本机已有 Java、Maven、Docker 等工具；如果失败，先执行 `pnpm check` 查看缺失项。
5. 当前脚本只服务项目初始化和工程协作，不生成业务类、数据库表结构、接口字段或测试数据。
6. 后续如小组确定数据库设计、接口设计和模块职责，可在本指南基础上补充数据库迁移、接口文档生成等脚本。
