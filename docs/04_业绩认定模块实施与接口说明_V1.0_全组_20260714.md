# 业绩认定模块实施与接口说明

> 版本：V1.0
> 日期：2026-07-14
> 负责人：全组

## 1. 业务边界

M18 用于办理工作业绩的填报、佐证材料关联、审核认定、参与人维护、认定标准版本管理和分类统计。模块不修改课程、课题、评价或申报来源数据；来源对象仅用于追溯和权限校验。当前支持的来源类型为申报档案、科研课题、实验课程、实验记录和培训计划，来源名称快照由服务端读取来源对象生成，客户端不能伪造。来源引用会复用来源模块的行级可见范围：课题限负责人或有效成员，课程限负责人/授课教师或学生可见的已发布课程，实验记录限记录人、课程教师或课题成员，培训计划限负责人、讲师或参与人。

业绩归属人固定为 `perf_record.user_id`，创建人只能创建本人业绩。负责人必须同时是 `perf_participant` 中唯一 `is_primary=1` 的参与人，参与人统计与负责人统计据此区分。

参与人候选不是按当前操作者的 `perf_record` 数据范围枚举，而是按业绩负责人的协作范围确定：负责人有部门时，候选人必须同机构且同部门；负责人没有部门时，候选人必须同机构；负责人缺少机构和部门时，只能保留负责人本人。候选查询、新增和修改均使用这套规则，避免学生的 `self` 数据范围阻断同部门协作，也避免跨组织或跨部门关联。候选接口按姓名或账号关键字在服务端搜索并分页返回，每页默认 20 条、最多 50 条；写入时仍会再次校验协作范围，不能依赖前端候选列表。

## 2. 状态与权限

### 2.1 业绩状态机

```text
draft -> submitted -> approved
                 -> rejected -> submitted
```

| 状态        | 填报人                          | 审核人             | 说明                                                               |
| ----------- | ------------------------------- | ------------------ | ------------------------------------------------------------------ |
| `draft`     | 编辑、维护材料/参与人、提交     | 查看数据范围内记录 | 新建后的初始状态。                                                 |
| `submitted` | 查看                            | 审核通过或要求修改 | 提交时冻结标准快照；不能编辑材料和参与人。                         |
| `rejected`  | 编辑、维护材料/参与人、再次提交 | 查看数据范围内记录 | 对应“待修改”状态，保留审核意见。                                   |
| `approved`  | 查看                            | 查看               | 不允许直接修改、再次审核或撤回。未来纠错应新增作废和重新认定流程。 |

要求修改时审核意见必填，通过意见可选。审核人不得审核本人业绩；状态更新受乐观锁保护，第二个并发审核请求会收到 `RESOURCE_CONFLICT`。

### 2.2 权限矩阵

| 角色       | 关键权限                                       | 可执行操作                                           |
| ---------- | ---------------------------------------------- | ---------------------------------------------------- |
| 填报人     | `performance:record:view/create/update/submit` | 创建本人业绩、维护草稿或待修改记录、上传材料、提交。 |
| 审核人     | `performance:record:view/audit`                | 在数据范围内查看、审核通过或要求修改，不能自审。     |
| 标准管理员 | `performance:standard:view/manage`             | 创建、编辑草稿、创建新版本、发布、停用标准。         |
| 系统管理员 | `performance:*`                                | 按全量数据范围执行上述操作。                         |

列表、详情、材料预览/下载和统计均使用服务端权限码与数据范围二次校验；参与人维护在业绩记录权限校验后，还会按负责人协作范围二次校验候选用户与写入用户。

## 3. 标准版本与快照

标准生命周期为 `draft -> published -> disabled`。仅草稿可编辑；草稿不能重复创建新版本，已发布或已停用的版本才可作为新版本来源。发布后的规则不可原地修改，必须通过新版本接口创建新的草稿版本。标准包含标准编号、版本号、业绩类型、等级规则、适用起止时间、材料要求、最少材料数、发布人和发布时间。

业绩提交时只接受处于 `published` 且在适用期内的标准，并冻结标准编号、版本、名称和认定规则到 `perf_record`。历史业绩继续使用冻结快照，不会因标准停用或新版本发布改变。

材料要求由标准版本的 `material_required`、`min_material_count` 控制。标准要求材料时，提交前必须达到最低数量；同一文件不能重复关联同一业绩，提交后材料冻结。冻结规则同时覆盖业绩材料专用接口和通用文件关联接口，避免绕过业务接口增删材料；业绩佐证材料始终保持私有，不能通过通用接口发布为匿名可见文件。

## 4. 数据模型和迁移

迁移文件：`V20260714_018__complete_performance_recognition.sql`、`V20260714_019__forward_fix_performance_history_backfill.sql`、`V20260714_020__harden_performance_participant_uniqueness.sql`。

| 对象               | 调整                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------- |
| `perf_standard`    | 增加版本、生命周期、等级规则、适用期、材料规则和发布审计字段；唯一性调整为“标准编号 + 版本”。 |
| `perf_record`      | 增加等级、发生时间、来源名称快照及标准快照字段。                                              |
| `perf_participant` | 新增参与人表，记录参与角色、排序和负责人标识；数据库约束保证同一业绩中的有效参与人不重复。    |

迁移将旧标准按原启用状态初始化为 `published` 或 `disabled`，版本号为 `1`；旧业绩的发生时间取创建时间、等级标记为 `unspecified`；每条旧业绩生成一条负责人参与记录；已关联标准会回填标准快照。`019` 是前向修复，确保未关联标准的旧业绩同样回填发生时间，并补齐缺失的标准快照。

执行前应备份目标库并检查迁移状态；执行后应校验业绩数量、负责人参与记录、标准版本唯一性和快照回填。Flyway 不对生产库做回滚，异常通过新的前向修复迁移处理。

## 5. 接口清单

所有接口要求 JWT。基础路径为 `/api`。

| 功能                 | 方法与路径                                                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 业绩列表、创建       | `GET/POST /performances`                                                                                                            |
| 业绩详情、编辑       | `GET/PUT /performances/{id}`                                                                                                        |
| 提交、审核           | `POST /performances/{id}/submissions`；`POST /performances/{id}/audit-records`                                                      |
| 材料维护             | `GET/POST /performances/{id}/materials`；`DELETE /performances/{id}/materials/{relationId}`                                         |
| 参与人维护           | `GET/POST /performances/{id}/participants`；`PUT/DELETE /performances/{id}/participants/{participantId}`                            |
| 参与人候选           | `GET /performances/{id}/participants/participant-users?keyword={姓名或账号}&pageNum=1&pageSize=20`                                  |
| 统计                 | `GET /performance-statistics`                                                                                                       |
| 标准列表、创建、编辑 | `GET/POST /performance-standards`；`PUT /performance-standards/{id}`                                                                |
| 版本与生命周期       | `POST /performance-standards/{id}/versions`；`POST /performance-standards/{id}/publish`；`POST /performance-standards/{id}/disable` |

审核请求使用 `{ "decision": "approved|rejected", "comment": "..." }`。审核人由当前 JWT 决定，客户端传递的认定人 ID 不被采信。

## 6. 统计口径与错误码

默认统计对象是业绩记录，负责人统计使用 `perf_record.user_id`；参与人统计通过 `participantUserId` 筛选，按参与过的业绩记录计数，不做多人分摊。业务周期默认使用 `occurredAt`，提交时间和认定时间保留用于审核追溯。

业务错误使用统一返回码：参数或状态不合法为 `VALIDATION_ERROR`，无权限和自审为 `FORBIDDEN`，标准失效/材料不足/重复参与人为 `CONFLICT` 或明确业务提示，并发终态审核为 `RESOURCE_CONFLICT`。

## 7. Web 工作台

前端路由为 `/performance`，要求 `performance:record:view`；看板待办使用 `/performance?performanceId={id}` 直接打开对应详情。页面包含业绩工作台和认定标准：支持填报、编辑、材料上传关联、受权限保护的材料预览/下载、参与人新增/编辑/移除、提交、审核、标准草稿编辑/新版本/发布/停用。参与人详情返回姓名和账号；前端将内部角色标识映射为中文，负责人显示为“负责人”，不会暴露内部 `owner` 标识。候选下拉框由业绩模块专用接口按姓名或账号远程检索并滚动加载，填报人无需额外拥有用户管理权限。若材料关联失败，前端会删除本次未绑定上传，避免遗留孤立文件。标准选择器按服务端分页按需加载全部已发布标准，所有规则仍以服务端校验为准。
