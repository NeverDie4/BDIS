## 1. 文档定位

本文档记录个人设置模块的实际完成情况、遗留问题和后续依赖。设计原则、接口结构和数据库模型继续以《个人设置模块详细设计方案 V0.5》为基线；本清单以当前代码和验证结果为事实来源，并在后续实施中持续更新。

状态定义：

- 已完成：接口、页面和主要行为均已接入。
- 部分完成：数据可以保存，但尚未在系统中完整生效，或存在明确体验缺口。
- 未实现：只有占位、设计或数据结构，尚不能形成用户可用功能。
- 外部依赖：需要对应业务模块、通知基础设施或全局设计确认后继续。

## 3. 当前优先级建议

| 优先级 | 工作项                                   | 原因                                                                   |
| ------ | ---------------------------------------- | ---------------------------------------------------------------------- |
| P0     | 修复头像显示链路和普通用户头像上传授权   | 当前接口看似可用，但用户可能无法上传，上传后界面也不会显示真实头像     |
| P0     | 补齐设置页请求失败状态和会话操作错误反馈 | 避免接口失败时只剩空白、Skeleton 或无反馈操作                          |
| P1     | 建立统一日期时间格式化工具并应用时区偏好 | 当前时区设置没有实际用户价值                                           |
| P1     | 完善程序化路由离开保护                   | 头像菜单等 `router.push` 导航可能绕过未保存提醒                        |
| P1     | 优化乐观锁冲突恢复                       | 多设备修改时需要可操作的恢复路径                                       |
| P2     | 决定单一语言、内容密度控件是否暂时隐藏   | 避免展示保存后不生效或没有可选项的设置                                 |
| P2     | 增加个人设置前端自动化测试               | 设置模块已经涉及鉴权、路由、并发保存和全局行为，人工验证不足以长期维护 |

## 4. 外部模块接入约定

教师、学生、采集和审核设置继续使用现有命名空间注册机制，不为不同角色复制设置页面。对应业务模块接入时应同时提供：

1. 明确的字段、默认值和取值范围。
2. 后端命名空间处理器的字段白名单与角色或权限校验。
3. 前端设置组件及保存、重置、错误状态。
4. 业务页面读取并实际应用偏好的位置。
5. 至少一组后端权限测试和前端可见性测试。

只有“可以保存”但业务页面不读取的字段，仍按“部分完成”处理，不能标记为已完成。
