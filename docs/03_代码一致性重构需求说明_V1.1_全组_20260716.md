# BDIS 代码一致性重构需求说明

> 版本：V1.1
> 日期：2026-07-16
> 负责人：全组
> 适用范围：后端包结构、请求对象命名、分页参数兼容与相关前端调用
> 当前状态：冻结后技术债清单，不在本期继续实施。

## 1. 背景与目标

多次功能分支合并后，项目已经能够编译和运行，但存在三类不影响当前功能、会增加后续维护成本的一致性问题：

本文档保留目标结构、非目标和验收标准，供后续迭代分阶段执行；冻结期不得以此为由进行跨模块重构。

| 问题 | 当前状态 | 目标状态 |
| --- | --- | --- |
| 业务包结构 | `audit`、`dashboard`、`file`、`soap` 分散在 `com.bdis.*` 与 `com.bdis.modules.*` | 业务代码统一位于 `com.bdis.modules.<module>` |
| 请求对象后缀 | Controller 入参同时使用 `DTO`、`Request`、`Query`、`QueryRequest` | 按对象边界使用固定后缀 |
| 分页请求参数 | 同时存在 `page/size` 与 `pageNum/pageSize` | 新接口统一 `page/size`，旧接口经过兼容期迁移 |

本重构只统一代码组织和接口命名，不新增业务功能，不修改数据库表结构，不改变权限边界，也不借机重写现有业务逻辑。

## 2. 强制约束

### 2.1 包结构

1. 新业务代码必须放入 `com.bdis.modules.<module>`。
2. 全局配置放入 `com.bdis.config`，跨模块基础能力放入 `com.bdis.common`。
3. `audit`、`dashboard`、`file`、`soap` 按模块整体迁移 Controller、Service、ServiceImpl、DTO、Query、VO、Component 和 Integration 类。
4. 迁移只改变 package 与 import，不改变 Controller 路径、Spring Bean 名称、Service 方法语义和数据库映射。
5. Mapper 接口与 XML namespace 必须始终一致；只使用 MyBatis-Plus `BaseMapper` 的接口不创建空壳 XML。

### 2.2 请求与响应对象

1. 仅用于 Controller HTTP 入参的对象使用 `XxxRequest`。
2. 仅用于 HTTP 查询参数的对象使用 `XxxQueryRequest`。
3. 可跨 Service、任务或集成边界传递的对象使用 `XxxDTO`。
4. 可在多个入口复用的业务查询对象使用 `XxxQuery`。
5. 返回给客户端的对象使用 `XxxVO`；不得直接返回 Entity。
6. 不得保留字段完全相同、只有 DTO/Request 后缀不同的重复类型。

### 2.3 分页契约

1. 新接口的请求参数统一为 `page`、`size`，页码从 1 开始。
2. 分页响应统一为 `records`、`page`、`size`、`total`。
3. 现有 `pageNum`、`pageSize` 接口在迁移期必须同时接受旧参数与新参数，旧参数标记为兼容输入。
4. 前端和 mobile 全部切换到 `page`、`size` 后，才能删除旧参数绑定。
5. 同时传入新旧参数且值不一致时，以 `page`、`size` 为准，并记录弃用提示。

## 3. 实施顺序

### 3.1 第一阶段：模块包迁移

按 `audit -> file -> dashboard -> soap` 顺序实施。每个模块使用独立提交，更新源码、测试 package、import 和文档引用后立即运行后端测试，不跨模块混改。

### 3.2 第二阶段：对象后缀统一

以 Controller 为入口逐个追踪对象用途。只在能够一次性更新生产代码、测试和调用方时改名；不做全仓库无差别替换。

### 3.3 第三阶段：分页兼容迁移

先增加兼容绑定和回归测试，再更新 Web 与 mobile 请求，最后经过一个明确的弃用周期移除 `pageNum`、`pageSize`。兼容期内不得改变分页默认值和最大页大小限制。

## 4. 非目标

本次一致性重构不得包含以下内容：

1. 数据库 migration、表名、字段名或索引调整。
2. REST 路径、HTTP 方法、鉴权规则或数据权限变化。
3. Entity 字段、业务状态流转或日志策略重写。
4. 引入新的框架、ORM 或通用基础层。
5. 与一致性无关的页面改版和业务功能开发。

## 5. 验收标准

每个阶段必须同时满足：

1. `pnpm validate` 通过，后端测试数量不得无理由减少。
2. `pnpm build:mobile:h5` 通过。
3. Maven Spotless 与 Checkstyle 通过。
4. Controller 路径、OpenAPI 请求响应和权限测试保持不变。
5. Mapper XML 可加载，namespace、statement id 与 Mapper 方法一致。
6. 数据库详细设计、Entity 和 Flyway migration 不产生差异。
7. Web 与 mobile 分页列表在新旧参数下返回相同结果。
8. 工作区不存在构建产物、日志、临时文件或失效文档链接。

## 6. 完成定义

只有当四个拆分业务包全部迁入 `com.bdis.modules`、HTTP 请求对象边界统一、所有客户端停止发送旧分页参数，并通过上述验收标准后，才能关闭本重构任务。在此之前，新增代码必须遵守目标规范，避免继续扩大兼容范围。
