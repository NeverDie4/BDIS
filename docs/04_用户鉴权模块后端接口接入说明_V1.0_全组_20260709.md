# 用户鉴权模块前后端接口与后端接入说明

> 版本：V1.0  
> 日期：2026-07-09  
> 适用范围：M01 身份认证、M02 用户角色、M03 权限控制，以及其他业务模块接入鉴权能力  
> 接口前缀：`/api`

## 1. 接入边界

1. 系统不提供公开注册入口，用户由管理员创建；首个管理员由初始化接口创建。
2. 除登录、初始化和接口文档外，所有接口都需要 `Authorization: Bearer <accessToken>`。
3. 前端接口用于登录、渲染菜单、控制按钮、维护权限后台页面；真正的业务安全必须由后端再次校验。
4. 后端其他业务模块优先注入 Java Service 或使用注解，不建议模块之间通过 HTTP 互调鉴权接口。
5. 客户端传来的 `ownerUserId`、`organizationId`、`departmentId` 只能用于前端体验或调试；最终资源归属必须由后端业务模块从数据库查询后再判断。
6. 用户身份、菜单权限、按钮权限和数据范围统一由角色决定；用户账号只维护基础资料和角色绑定，不再维护独立的用户类型。

## 2. 前端可调用接口

### 2.0 通用响应格式

普通响应统一包一层 `Result<T>`：

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {},
  "timestamp": "2026-07-09T08:00:00+08:00"
}
```

分页响应的 `data` 为：

```json
{
  "records": [],
  "page": 1,
  "size": 10,
  "total": 0
}
```

前端请求工具应只把 `data.data` 交给页面；401 清登录态，403 保持登录但提示无权限。

### 2.1 认证与当前用户

| 功能 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 初始化管理员 | `POST` | `/api/auth/bootstrap-admin` | 仅系统无用户且初始化令牌正确时可用。 |
| 登录 | `POST` | `/api/auth/sessions` | 使用账号密码创建登录会话，返回 access token。 |
| 退出当前端 | `DELETE` | `/api/auth/sessions/current` | 拉黑当前 token；允许多端登录。 |
| 当前用户 | `GET` | `/api/auth/me` | 返回当前用户、角色、权限、组织和部门信息。 |

登录请求：

```json
{
  "username": "admin",
  "password": "password"
}
```

登录响应核心字段：

```json
{
  "accessToken": "jwt",
  "tokenType": "Bearer",
  "expiresIn": 7200,
  "user": {
    "userId": 1,
    "username": "admin",
    "realName": "系统管理员",
    "organizationId": 1,
    "departmentId": 1,
    "roleCodes": ["ADMIN"],
    "roleIds": [1],
    "permissions": ["*"]
  }
}
```

### 2.2 菜单和按钮

| 功能 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 当前用户菜单 | `GET` | `/api/me/menus` | 返回当前用户可见后台菜单树。 |
| 当前用户按钮权限 | `GET` | `/api/me/buttons?menuCode=user_management` | 返回当前用户在指定菜单下可用按钮权限。 |

前端使用建议：

1. 登录成功后保存 `accessToken`，后续请求放入 `Authorization` Header。
2. 进入后台时调用 `/api/auth/me` 和 `/api/me/menus`。
3. 页面按钮可使用 `/api/me/buttons` 或 `/api/auth/me` 中的 `permissions` 控制显示。
4. 收到 401 时清理 token 并跳转登录页；收到 403 时提示无权限。

### 2.3 权限后台管理接口

这些接口主要供后台管理页面使用，前端只需要做可运行的基础界面即可。

| 资源 | 方法与路径 | 说明 |
| --- | --- | --- |
| 用户 | `GET /api/users` | 用户列表，支持 `page`、`size`、`keyword`、`status`、`roleId`、`organizationId`、`departmentId`。 |
| 用户 | `POST /api/users` | 新增用户；必须分配至少一个角色。 |
| 用户 | `GET /api/users/{userId}` | 用户详情。 |
| 用户 | `PUT /api/users/{userId}` | 整体更新用户。 |
| 用户 | `PATCH /api/users/{userId}` | 局部更新用户。 |
| 用户 | `DELETE /api/users/{userId}` | 删除用户；当前登录用户不能删除自己。 |
| 用户角色 | `PUT /api/users/{userId}/roles` | 给用户分配启用状态的角色。 |
| 角色 | `GET /api/roles` | 角色列表，支持分页、关键词和状态筛选。 |
| 角色 | `POST /api/roles` | 新增角色。 |
| 角色 | `GET /api/roles/{roleId}` | 角色详情。 |
| 角色 | `PUT /api/roles/{roleId}` | 更新角色。 |
| 角色 | `DELETE /api/roles/{roleId}` | 删除未被用户使用的角色，并清理角色权限和数据范围配置。 |
| 角色权限 | `PUT /api/roles/{roleId}/permissions` | 给角色分配启用状态的权限点。 |
| 组织 | `GET /api/organizations` | 组织列表。 |
| 组织 | `POST /api/organizations` | 新增组织。 |
| 组织 | `GET /api/organizations/{organizationId}` | 组织详情。 |
| 组织 | `PUT /api/organizations/{organizationId}` | 更新组织。 |
| 组织 | `DELETE /api/organizations/{organizationId}` | 无部门、无用户引用时可删除。 |
| 部门 | `GET /api/departments` | 部门树，支持 `organizationId`、`keyword`、`status`。 |
| 部门 | `POST /api/departments` | 新增部门。 |
| 部门 | `GET /api/departments/{departmentId}` | 部门详情。 |
| 部门 | `PUT /api/departments/{departmentId}` | 更新部门。 |
| 部门 | `DELETE /api/departments/{departmentId}` | 无子部门、无用户引用时可删除。 |
| 菜单 | `GET /api/menus` | 菜单树。 |
| 菜单 | `POST /api/menus` | 新增菜单。 |
| 菜单 | `GET /api/menus/{menuId}` | 菜单详情。 |
| 菜单 | `PUT /api/menus/{menuId}` | 更新菜单。 |
| 菜单 | `DELETE /api/menus/{menuId}` | 无子菜单、无权限点绑定时可删除。 |
| 权限点 | `GET /api/permissions` | 权限点列表，支持 `permissionType`、`menuId`、`keyword`、`status`。 |
| 权限点 | `POST /api/permissions` | 新增权限点。 |
| 权限点 | `GET /api/permissions/{permissionId}` | 权限点详情。 |
| 权限点 | `PUT /api/permissions/{permissionId}` | 更新权限点。 |
| 权限点 | `DELETE /api/permissions/{permissionId}` | 删除权限点，并清理角色权限关系。 |
| 数据范围 | `GET /api/roles/{roleId}/data-scopes` | 查询角色数据范围配置。 |
| 数据范围 | `POST /api/data-scopes` | 保存角色数据范围配置。 |
| 数据范围 | `DELETE /api/data-scopes/{dataScopeId}` | 删除数据范围配置。 |

### 2.4 前端辅助权限判定

| 功能 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 权限判定 | `POST` | `/api/authorization-decisions` | 可用于前端预判按钮或操作提示，不作为最终安全依据。 |
| 当前用户数据范围 | `GET` | `/api/data-scopes/current?resourceType=herb_growth_record` | 可用于前端展示当前用户数据范围。 |

权限判定请求字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `resourceType` | 是 | 资源类型，建议使用表名式小写下划线，例如 `herb_growth_record`。 |
| `action` | 是 | 动作，例如 `view`、`create`、`update`、`delete`、`audit`。 |
| `permissionCode` | 否 | 显式权限码；业务模块建议传该字段，例如 `growth:record:audit`。 |
| `resourceId` | 否 | 业务资源 ID，当前用于透传和后续扩展。 |
| `ownerUserId` | 否 | 资源所属用户或创建人 ID，用于本人范围判断。 |
| `organizationId` | 否 | 资源所属机构 ID，用于机构范围判断。 |
| `departmentId` | 否 | 资源所属部门 ID，用于部门范围判断。 |

示例：

```json
{
  "resourceType": "herb_growth_record",
  "resourceId": 1001,
  "action": "audit",
  "permissionCode": "growth:record:audit",
  "ownerUserId": 12,
  "organizationId": 3,
  "departmentId": 8
}
```

响应核心字段：

```json
{
  "allowed": true,
  "reason": "允许访问",
  "dataScope": {
    "scopeType": "department",
    "organizationIds": [],
    "departmentIds": [8],
    "customRules": [],
    "selfIncluded": false,
    "allIncluded": false
  }
}
```

## 3. 后端其他模块通用方法

### 3.1 获取当前用户

适用场景：保存创建人、填报人、采集人、审核人，或读取当前用户组织部门。

```java
CurrentUser user = SecurityUtils.currentUser();
Long userId = user.getUserId();
Long organizationId = user.getOrganizationId();
Long departmentId = user.getDepartmentId();
```

### 3.2 注解式权限校验

推荐业务模块 Controller 或 Service 方法使用：

```java
@RequirePermission("growth:record:view")
@GetMapping("/growth-records")
public Result<PageResult<GrowthRecordVO>> page(GrowthRecordQuery query) {
    return Result.success(growthRecordService.page(query));
}
```

说明：

1. 注解值必须是 `auth_permission.permission_code` 中存在且已分配给用户角色的权限码。
2. 自调用方法不会触发 Spring AOP；需要在对外 Controller 方法或被 Spring 代理的 Service 方法上使用。
3. 管理后台已有接口仍可继续手动调用 `authorizationService.requirePermission(...)`。

### 3.3 手动权限校验

适用场景：一个接口内部有多个操作分支，需要按条件校验不同权限。

```java
authorizationService.requirePermission("growth:record:audit");

if (authorizationService.hasPermission("growth:record:export")) {
    // 执行导出相关逻辑
}
```

### 3.4 后端资源级权限判定

如果业务模块已经从数据库查出资源归属，可以调用：

```java
AuthorizationDecisionDTO dto = new AuthorizationDecisionDTO();
dto.setResourceType("herb_growth_record");
dto.setPermissionCode("growth:record:audit");
dto.setAction("audit");
dto.setOwnerUserId(record.getCreatedBy());
dto.setOrganizationId(record.getOrganizationId());
dto.setDepartmentId(record.getDepartmentId());

AuthorizationDecisionVO decision = authorizationService.decide(dto);
if (!decision.isAllowed()) {
    throw new ForbiddenException(decision.getReason());
}
```

注意：最终判断必须使用后端查出的 `record` 归属信息，不能直接信任前端传来的归属字段。

### 3.5 数据范围应用到查询

业务模块使用 MyBatis-Plus 查询时，可调用：

```java
LambdaQueryWrapper<GrowthRecordEntity> wrapper = new LambdaQueryWrapper<>();
dataScopeService.applyToQuery(
        wrapper,
        "herb_growth_record",
        GrowthRecordEntity::getCreatedBy,
        GrowthRecordEntity::getOrganizationId,
        GrowthRecordEntity::getDepartmentId);
```

参数说明：

| 参数 | 说明 |
| --- | --- |
| `wrapper` | 当前业务查询条件。 |
| `resourceType` | 资源类型，用于匹配 `auth_data_scope.resource_type`。 |
| `ownerField` | 本人范围字段，可传 `createdBy`、`collectorId`、`submitterId` 等。 |
| `organizationField` | 机构范围字段。 |
| `departmentField` | 部门范围字段。 |

行为说明：

1. 当前用户是 `all` 范围时，不追加条件。
2. `self`、`organization`、`department` 会按 OR 合并。
3. 如果没有任何可应用字段，默认追加空结果条件，避免误放权。
4. `customRules` 当前只返回，不自动拼 SQL；业务模块需要自定义解释时应单独处理。

### 3.6 查询当前用户数据范围

只需要拿到范围结果、不想直接改查询条件时，可调用：

```java
DataScopeResultVO scope = dataScopeService.resolveForCurrentUser("herb_growth_record");
```

## 4. 数据范围类型

| scopeType | 含义 | 业务模块落地方式 |
| --- | --- | --- |
| `all` | 全部数据 | 不追加范围条件。 |
| `organization` | 机构数据 | 使用业务表的机构字段过滤。 |
| `department` | 部门数据 | 使用业务表的部门字段过滤。 |
| `self` | 本人数据 | 使用创建人、采集人、填报人等用户字段过滤。 |
| `custom` | 自定义规则 | 当前保留 `customRules`，由具体业务模块解释。 |
| `none` | 无数据范围 | 应返回空结果或拒绝访问。 |

## 5. 权限码和资源类型命名

权限码建议统一为：

```text
模块:资源:动作
```

常用动作：

| 动作 | 含义 |
| --- | --- |
| `view` | 查看、列表、详情 |
| `create` | 新增 |
| `update` | 编辑 |
| `delete` | 删除 |
| `submit` | 提交 |
| `audit` | 审核 |
| `archive` | 归档 |
| `download` | 下载 |
| `export` | 导出 |
| `import` | 导入 |

示例：

| 模块 | resourceType | 权限码示例 |
| --- | --- | --- |
| 生长采集 | `herb_growth_record` | `growth:record:view`、`growth:record:create` |
| 采集审核 | `herb_growth_record` | `growth:record:audit` |
| 文件资源 | `sys_file_resource` | `file:resource:download` |
| 实验课程 | `edu_course` | `course:course:view` |
| 课题研究 | `research_project` | `research:project:update` |
| 评价申报 | `eval_application` | `declaration:application:audit` |
| 业绩认定 | `perf_record` | `performance:record:submit` |

新增业务模块菜单和权限点时，应通过 Flyway 迁移脚本或权限后台写入 `auth_menu`、`auth_permission`，并将需要的权限分配给对应角色。
