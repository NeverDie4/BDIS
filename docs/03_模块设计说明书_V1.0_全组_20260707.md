# 生物医药数字信息系统模块设计说明书

> 版本：V1.0
> 适用阶段：概要设计与详细设计前期
> 说明：本文件仅描述模块划分、模块职责、模块依赖和模块独立性，不包含具体接口路径、HTTP 方法、请求体或响应体设计。

## 1. 文档目的

本文档用于说明生物医药数字信息系统的模块划分、模块职责、模块边界、模块间依赖关系和模块独立性设计。文档面向项目概要设计、详细设计、代码实现、测试设计和答辩说明使用。

本文件不包含具体接口路径、HTTP 方法、请求参数、响应格式和状态码设计。相关内容应放入独立的接口设计规范文件中，避免需求设计、模块设计和接口设计混杂。

## 2. 模块设计原则

| 设计原则 | 具体要求 |
| --- | --- |
| 职责单一 | 每个模块只完成一个明确子功能，避免把无关功能合并到同一模块中。 |
| 高内聚 | 模块内部功能围绕同一业务目标组织，优先达到功能内聚，其次为顺序内聚或信息内聚。 |
| 低耦合 | 模块之间通过业务标识、标准数据对象和抽象服务进行数据传递，尽量采用数据耦合，减少控制耦合。 |
| 规模适中 | 过大的功能域继续拆分，过小且职责相近的能力适当合并，避免模块颗粒度失衡。 |
| 边界清晰 | 模块只控制自身职责范围内的数据和流程，模块作用域应位于控制域之内。 |
| 可测试可维护 | 模块应能独立设计、独立开发、独立测试和独立替换，降低后期维护成本。 |

## 3. 系统总体模块结构

根据系统业务特点，将系统划分为四类模块：基础支撑模块、中药材核心数据模块、教学科研与管理业务模块、集成与展示模块。基础支撑模块提供全局公共能力，业务模块围绕具体业务对象组织，集成与展示模块负责外部系统适配和统计展示。

## 5. 基础支撑模块设计

### M01 身份认证模块

模块职责：身份认证模块只负责用户身份确认和登录会话维护，是系统访问入口的基础支撑能力。

主要功能：

- 用户登录状态识别

- 登录会话维护

- 当前用户信息获取

- 登录失效处理

边界说明：不负责用户资料维护、角色分配和业务权限判断。用户资料由用户角色模块维护，具体权限判断由权限控制模块完成。

耦合控制：与用户角色模块之间只传递账号、用户标识、状态和角色摘要信息，属于数据耦合。

### M02 用户角色模块

模块职责：用户角色模块负责维护系统中的用户、角色、组织层级和用户角色关系。

主要功能：

- 用户档案维护

- 角色维护

- 组织层级维护

- 用户角色绑定

- 账号启用和停用

边界说明：不负责登录会话，不负责具体业务权限判定，不参与药材、课程、申报等业务数据处理。

耦合控制：向身份认证模块、权限控制模块和操作审计模块提供用户与角色基础数据。

### M03 权限控制模块

模块职责：权限控制模块负责根据用户角色、组织层级、菜单权限和数据范围判断用户是否允许访问某个功能或数据。

主要功能：

- 菜单权限判断

- 功能权限判断

- 数据范围判断

- 按钮级权限判断

边界说明：不直接执行业务操作，不修改业务数据，只返回权限判断结果和可访问范围。

耦合控制：业务模块仅传递用户标识、资源类型、资源标识和操作类型，权限模块返回允许或拒绝。

### M04 数据字典模块

模块职责：数据字典模块负责维护系统通用分类、状态、枚举和基础配置项。

主要功能：

- 药材分类字典

- 文件类型字典

- 审核状态字典

- 评价等级字典

- 业绩类别字典

边界说明：不参与业务流程控制，不保存具体业务记录。

耦合控制：属于公共基础模块，允许较高扇入，但自身不主动调用业务模块，保持低扇出。

### M05 文件资源模块

模块职责：文件资源模块统一处理图片、文档、视频、图谱、课件、申报附件和业绩材料等文件资源。

主要功能：

- 文件上传与存储

- 文件元数据维护

- 图片预览

- 文件下载

- 视频播放链接管理

- 文件与业务对象关联

边界说明：不理解具体业务含义，不直接修改药材、课程、评价、业绩等业务实体。

耦合控制：通过业务类型、业务标识和文件标识建立关联，避免文件模块反向依赖具体业务模块。

### M06 操作审计模块

模块职责：操作审计模块负责记录登录、查询、上传、下载、审核、归档、认定和外部交换等关键行为。

主要功能：

- 登录日志记录

- 业务操作记录

- 文件访问记录

- 审核操作记录

- 外部交换记录查询

边界说明：不控制业务流程，不决定业务状态，只记录和查询日志。

耦合控制：属于高扇入、低扇出的公共模块，可被多个业务模块调用。

## 6. 中药材核心数据模块设计

### M07 药材档案模块

模块职责：药材档案模块维护中药材基础信息，是系统核心主数据模块。

主要功能：

- 药材基础信息维护

- 药材分类和别名维护

- 药材功效和简介维护

- 药材图片关联

- 药材详情查询

边界说明：不维护地图点位、生长采集、课程课题和申报材料，只提供药材主数据。

耦合控制：其他模块通过药材标识关联药材，属于数据耦合。

### M08 基地与地图模块

模块职责：基地与地图模块负责维护中药材基地、产地、区县、经纬度和重庆分布地图点位。

主要功能：

- 基地信息维护

- 产地信息维护

- 地图点位维护

- 按药材筛选点位

- 按区县筛选点位

- 重庆地图展示数据组织

边界说明：只回答药材在哪里，不维护药材功效、图谱、课程、评价和申报信息。

耦合控制：通过药材标识、基地标识和点位标识与药材档案模块形成数据耦合。

### M09 生长采集模块

模块职责：生长采集模块负责接收移动网页版提交的中药材生长数据并形成采集记录。

主要功能：

- 移动网页版采集表单支撑

- 采集数据保存

- 采集图片关联

- 采集地点记录

- 生长环境指标记录

- 形态指标记录

边界说明：只负责采集记录创建和基础维护，不负责审核、归档和溯源展示。

耦合控制：依赖药材档案模块确认药材对象，依赖文件资源模块保存现场图片。

### M10 采集审核与溯源模块

模块职责：采集审核与溯源模块负责采集记录的提交、审核、退回、归档和追溯查询。

主要功能：

- 采集记录提交

- 审核通过

- 审核退回

- 采集记录归档

- 审核历史查询

- 溯源链路查询

边界说明：只改变采集记录的流程状态，不修改药材档案、基地信息和文件实体。

耦合控制：围绕提交、审核、归档、追溯的顺序组织，属于顺序内聚。

### M11 图谱知识模块

模块职责：图谱知识模块负责图谱资料管理、人工比对记录和药材知识关系展示。

主要功能：

- 图谱文件登记

- 样本图谱关联

- 人工比对结果记录

- 药材知识卡片组织

- 药材关系图数据组织

边界说明：本期不直接实现复杂图像识别算法，算法能力作为后续扩展服务接入。

耦合控制：依赖药材档案和文件资源模块，通过药材标识和文件标识关联数据。

## 7. 教学科研与管理业务模块设计

### M12 实验课程模块

模块职责：实验课程模块负责管理实验课程、实验步骤、课程资料和视频资源链接。

主要功能：

- 课程基础信息维护

- 实验步骤维护

- 课程资料关联

- 视频资源链接维护

- 课程发布状态维护

边界说明：只管理课程本身，不管理课题研究、培训活动和实验过程记录。

耦合控制：课程资料通过文件资源模块关联，关联药材通过药材标识表达。

### M13 课题研究模块

模块职责：课题研究模块负责维护课题信息、参与人员、研究周期、关联药材和课题材料。

主要功能：

- 课题基础信息维护

- 课题成员维护

- 研究周期记录

- 关联药材维护

- 课题材料管理

边界说明：不记录具体实验过程，实验过程交由实验记录模块完成。

耦合控制：通过成员标识、药材标识和文件标识与其他模块数据耦合。

### M14 实验记录模块

模块职责：实验记录模块负责记录课程或课题下的实验过程、实验结果、附件和归档信息，可作为轻量版实验电子记录本。

主要功能：

- 实验过程记录

- 实验结果记录

- 实验附件关联

- 实验记录修改

- 实验记录归档

边界说明：不修改课程和课题基础信息，只通过课程标识或课题标识建立归属关系。

耦合控制：实验记录围绕创建、修改、提交、归档形成顺序内聚。

### M15 培训过程模块

模块职责：培训过程模块负责培训计划、培训素材、参与人员、培训结果和反馈记录。

主要功能：

- 培训计划维护

- 培训素材关联

- 参与人员记录

- 培训结果记录

- 反馈评价记录

边界说明：不负责实验课程教学，不负责评价标准和申报档案，只输出培训档案。

耦合控制：依赖文件资源模块保存培训素材，依赖用户角色模块识别参与人员。

### M16 评价管理模块

模块职责：评价管理模块负责评价标准、评价任务、评价过程和评价结果。

主要功能：

- 评价标准维护

- 评价指标维护

- 评价任务创建

- 评价材料关联

- 评价评分记录

- 评价结果确认

边界说明：不负责申报档案汇总，只产生可被申报档案模块读取的评价结果。

耦合控制：通过药材标识、评价对象标识和文件标识与其他模块形成数据耦合。

### M17 申报档案模块

模块职责：申报档案模块负责将药材、采集记录、图谱资料、课程课题材料、评价结果和附件汇总成申报档案袋。

主要功能：

- 申报档案创建

- 关联药材数据

- 关联采集记录

- 关联评价结果

- 关联附件材料

- 申报材料清单生成

边界说明：只进行材料汇总和关联，不反向修改药材、采集、课程、评价等来源数据。

耦合控制：作为聚合模块扇出较高，但只读查询和材料关联可避免内容耦合。

### M18 业绩认定模块

模块职责：业绩认定模块负责工作业绩填报、材料提交、审核认定、退回修改和分类统计。

主要功能：

- 业绩填报

- 业绩材料关联

- 业绩提交

- 业绩审核

- 业绩退回

- 分类分级统计

- 认定标准维护

边界说明：不修改课程、课题和评价数据，业绩材料作为独立业务对象维护。

耦合控制：依赖文件资源模块保存佐证材料，依赖操作审计模块记录审核行为。

## 8. 集成与展示模块设计

### M19 SOAP 数据交换模块

模块职责：SOAP 数据交换模块负责模拟校内 SOAP 系统的数据交换，包括请求构造、响应解析、数据转换、导入和交换日志记录。

主要功能：

- SOAP 模拟请求

- SOAP 模拟响应

- XML 数据解析

- 标准导入对象转换

- 交换结果记录

- 失败信息记录

- 手动重试记录

边界说明：不直接嵌入药材或采集业务规则，不绕过业务模块直接修改核心业务数据。

耦合控制：先将外部数据转换为标准导入对象，再交由对应业务模块处理，降低内容耦合。

### M20 首页看板模块

模块职责：首页看板模块负责聚合系统统计数据，用于首页展示药材数量、基地数量、采集数量、课程数量、待审核事项和地图概览。

主要功能：

- 核心数量统计

- 最近采集记录摘要

- 待办事项摘要

- 地图概览统计

- 快捷入口数据组织

边界说明：只做统计展示，不控制任何业务状态，不修改任何业务数据。

耦合控制：允许较高扇出，但所有调用均为只读查询，避免对业务模块造成反向影响。

## 9. 模块间依赖关系

模块之间应优先通过业务标识、标准数据对象和抽象服务传递数据，不允许业务模块直接访问其他模块的内部数据结构。普通业务模块应保持低扇出，公共支撑模块允许高扇入。

## 10. 模块耦合设计

### 10.1 数据耦合

系统模块之间主要通过用户标识、角色标识、药材标识、基地标识、采集记录标识、文件标识、业务类型、业务标识、状态值和标准数据对象进行数据传递。该方式接口边界清晰，影响范围较小，属于推荐的数据耦合。

### 10.2 控制耦合控制

模块之间不应通过一个通用处理入口加动作类型参数控制多个业务流程。提交、审核、退回、归档等状态流转应由各自业务模块明确控制，避免出现万能处理模块。

### 10.3 公共耦合限制

系统不得依赖全局变量或共享上下文保存核心业务状态。Redis 仅用于缓存、临时状态、统计结果或会话信息，不作为长期业务数据的唯一存储。

### 10.4 内容耦合避免

一个模块不得直接修改另一个模块的内部数据结构或私有逻辑。例如，申报档案模块不得直接修改采集记录内容，SOAP 数据交换模块不得绕过药材档案模块直接写入药材核心数据。

## 11. 模块内聚设计

| 内聚类型 | 对应模块 | 说明 |
| --- | --- | --- |
| 功能内聚 | 身份认证、权限控制、文件资源、操作审计、基地与地图、生长采集、图谱知识、SOAP 数据交换 | 模块内部所有功能服务于同一明确功能目标。 |
| 信息内聚 | 用户角色、药材档案、实验课程、课题研究 | 模块围绕同一类业务信息对象进行维护。 |
| 顺序内聚 | 采集审核与溯源、实验记录、培训过程、评价管理、业绩认定 | 模块内部功能按照业务流程顺序组织。 |
| 通信内聚 | 申报档案、首页看板 | 模块围绕同一输出目标聚合多来源数据。 |

本设计避免偶然内聚，例如不将地图、文件、SOAP 和统计功能随意合并为综合管理模块；也避免逻辑内聚，例如不使用一个通用处理函数处理所有审核类业务。

## 12. 扇入与扇出设计

### 12.1 高扇入模块

权限控制模块、数据字典模块、文件资源模块和操作审计模块会被多个业务模块调用，属于合理高扇入模块。它们职责稳定、接口抽象、低扇出，适合沉淀为公共支撑能力。

### 12.2 低扇出业务模块

普通业务模块应尽量只依赖少量基础模块。例如药材档案模块主要依赖文件资源和数据字典；业绩认定模块主要依赖文件资源和操作审计；实验课程模块主要依赖药材档案和文件资源。

### 12.3 特殊聚合模块

申报档案模块、SOAP 数据交换模块和首页看板模块扇出相对较高，但其职责分别为材料汇总、外部适配和统计展示。它们不直接修改来源业务模块内部数据，因此可以接受较高扇出。

## 13. 模块作用域与控制域设计

| 模块 | 控制域 | 作用域限制 |
| --- | --- | --- |
| 生长采集模块 | 采集记录创建和基础维护 | 不审核、不归档、不修改药材档案。 |
| 采集审核与溯源模块 | 采集记录状态流转和追溯 | 不修改药材、基地和文件实体。 |
| 评价管理模块 | 评价标准、任务、评分和结果 | 不生成申报档案。 |
| 申报档案模块 | 申报材料汇总和材料关联 | 不修改评价结果和采集原始数据。 |
| 业绩认定模块 | 业绩填报、审核和统计 | 不修改课程、课题和评价数据。 |
| SOAP 数据交换模块 | 外部数据转换和交换记录 | 不绕过业务模块直接写核心表。 |
| 首页看板模块 | 统计展示 | 不控制任何业务状态。 |

## 15. 结论

本系统采用模块化设计思想，将系统划分为基础支撑、中药材核心数据、教学科研与管理业务、集成与展示四类模块。各模块围绕单一职责进行划分，模块内部尽量达到功能内聚、顺序内聚或信息内聚，避免将无关功能合并到同一模块中。

模块之间通过业务标识、标准数据对象和抽象服务进行数据传递，尽量采用数据耦合，限制公共耦合，避免内容耦合。文件资源、权限控制、操作审计等公共模块允许较高扇入，但保持低扇出；申报档案、SOAP 数据交换和首页看板作为聚合类模块，只进行材料汇总、接口适配和统计展示，不直接修改其他模块内部数据。

通过上述设计，系统具有较好的可理解性、可开发性、可测试性、可维护性和后续扩展能力，能够满足代码开发、文档提交和答辩展示的综合要求。
